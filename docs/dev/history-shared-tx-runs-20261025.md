## 共享什么，怎样查询

V11 去掉多次变化 posting 中每行重复的变长 TxNum，保留差分记录序号、128 行帧及 firstTx 目录。
单次变化内联项保留完整 TxNum/offset/ordinal。V9 的共享 ordinal→offset 表继续使用，不扫描 `.seg` 找位置。
新增表把单段内相同 TxNum 的连续记录合并成 run（包含维护位置，不等同于真实交易总数），每 256 个 run 一页：
TxNum 差分加正的行数；32 B 目录项和 64 B footer 各自认证边界、长度、覆盖与 CRC。
键、ID、顺序、规范字典摘要、旧值、`.seg/.idx` 及 MuHash 元素编码不变。

请求先把 TxNum 上下界转换为 ordinal 范围，每个私有 resolver 只计算一次，再筛选相关帧、解析选中的 TxNum 和 offset。
目录认证完整后才二分定位，目录上限 1 MiB；每个 reader 的解码 run 页缓存以 2 MiB payload 为上限（不含 Go 容器开销），有同步和淘汰，绑定源身份。
生产流式构建使用有界 scratch 文件记录 run，关闭/取消时回收自身临时文件；全为单次变化或超过目录上限，在消耗 posting ETL 前回退旧编码。
地址字典仍按页和文件自适应，TxNum 缩短引起键页/地址表选择变化也计入账目，不能假设它们字节不变。
旧 V7/V8/V9/V10 读取分支保持显式；旧二进制不能读取 V11。这里只转换固定副本，没有在线替换 manifest，既有生产文件不会自动缩小。格式细节见 [设计](../superpowers/specs/2026-10-25-history-shared-tx-runs.md)。
