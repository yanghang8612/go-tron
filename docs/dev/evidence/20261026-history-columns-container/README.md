# 物理格式 5 的阶段证据

`python3 verify.py` 只读验证三份 ZIP、各自内部清单、四份服务器上传包、
全部 2,145 个当前 Go／模块文件及原生检查回执。可以用 `--source-root` 指定源码。
它不连接服务器、不运行包内脚本、不改写数据库。

`local-source-and-harness.zip` 保存本地测试摘要、源码清单和首次原生准备脚本。
`native-progress-and-acceptance.zip` 保存实际上传包、后续完整验收脚本、
对照文件测试及 UTC 2026-10-25 17:47:52 的原生回执。

当时七项原生检查全部通过，全量转换完成 180 / 4,609 个文件；
已完成部分 `.seg` 的长度下降 59,609,991 B。完整转换、同页边界对照、
MuHash、真实历史恢复、HTTP 和最终物理闭环仍未完成。
**这些回执不能作为整库净收益或上线验收。**

`publish-control-and-live-progress.zip` 另保存冷发布对照脚本、本地用例和
UTC 18:08:41 的原始活进程回执：转换子进程仍在运行，完成 1,090 / 4,609 段，
已完成部分 `.seg` 长度下降 751,604,682 B；验收与冷发布计时仍在等待。
回执通过可见终端输出和界面复制取回，本地核对长度及 SHA256；没有从截图手工转写数值。

冷发布对照使用实际 `CompactHistoryDomain`、索引构建、fsync 和私有 manifest
发布路径，三个真实来源区间、格式 2／5 各四次计时，共 24 次，另有六次预热。
它是固定输入、暖缓存的合并发布对照：`MaxSteps` 显式取两份输入的聚合步数之和，
可能超过默认 256；不能当作默认调度、从热 history 首次构建或全节点同步吞吐。
它在全部 HTTP／MuHash 验收结束后才开始，避免污染查询计时。

服务器实验目录：`/data/gtron/history-record-columns-container-20261026-01`。
所有脚本只操作该目录及读取此前冻结的固定副本。保留所有原文件，
没有发布或启停生产 `gtron`。后续正式结果另行归档，不覆盖这份阶段证据。
