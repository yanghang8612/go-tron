### ABI 重复与 native codec

ContractMetadata 3,671 行、独立 ContractABI 3,430 行（均含旧代）。3,430 个 metadata 内嵌 ABI 与同 owner/generation 的独立 ABI **全部 proto.Equal**，不同/缺失 0；重复 ABI native 编码 **4,598,996 B**。应研究统一物理表示并在读取完整 SmartContract 时重建，而非直接删域；还需覆盖 ClearABI、历史查询和账户代切换。在这个切面体量不大。

通用 `statecodec` 的 integer/enum scalar 确为固定 8 B；可设计新 codec 的有符号/无符号 varint，并同步更新 `ReadContractRuntime` 等快速解析器。但账户 core/resource 已用专用紧凑编码。每行 Zstd 的“逻辑压缩很大、Snappy SST 只省不到 1 MB”也说明不能只用原值字节判断是否值得增加 CPU 与复杂度。此项暂不阻塞这轮创世同步。

内容寻址合约字节码另在 **03:35:48–03:35:49** 对同一离线库补查：**1,809 行**，key 83,214 B、code **11,499,696 B**，最大单份 68,843 B。逐份 Keccak 与 key 一致，Zstd 解码后逐字节一致，四组 SST 校验通过。Snappy 对照 **4,654,903 → 3,874,884 B**，仅再省 **780,019 B**；不压缩对照 11,651,407 → 3,887,947 B。代码已经按内容哈希去重；本次未分析哪些 hash 不再可达，不能据此删除。该切面没有足够收益将额外解压读路径列为优先项。原始证据为 `code-distribution.json`，source framed SHA `2bf0d3029dff2e1ab06aab079325ac026a17a6516791af48ade14e34e2c2a813`；该辅助表不属于上述三个 MuHash 源族，独立核验其内容哈希。

- `WriteCycleAccountVote` 保存完整 Account 的 native 表示，上游也序列化完整 Account。不能因奖励计算当前只读 votes 就只保留 votes/allowance；需保留逻辑完整账户，可后续研究共享内容或专用无损 codec。

## 5. 建议这一轮的范围与验收

1. **创世同步前的状态格式批次**：保留已完成的 Storage/Shielded；增加有界 `VotesIndex`，通用 8 B 物理值编码；账户地址省略在相同正确性门槛下可一并纳入。先固定最终 commitment/manifest scheme，避免新旧方案启动顺序导致误判 HEAD。
2. **优先实现冷文件原型**：ancient tx-index 相对定位（完整数据布局模型约 1.96 GB）；history `.idx` 4/16 KiB 页压缩（样本约 57%/63%）。固定样本完成新旧 reader/writer 对照、物理文件核验和随机查询基准后决定上线。
3. **进一步测量账户/resource 历史字段差分**，其未压缩旧值占比高，但当前没有物理收益结论。event-log 去交易哈希重复及通用 native varint 列为后续，不承诺在缺少延迟/成熟数据证据时一次全部上生产。
4. 冷文件局部格式通常可用独立 manifest、校验、可恢复迁移逐步升级；完成这些研究不必再次从创世同步。不能为了“一次到位”把尚未验证的冷查询代价都塞进本轮状态重建。

任何新状态格式合入前，必须验证完整 MuHash **3072 位 accumulator state 和 digest**（不能只比缓存 root）；全量/抽样历史 as-of、存在空值/零值/删除、代切换、同块多次修改、unwind/replay、maintenance 清空、快照导出导入后继续执行都应一致。逻辑不变的物理编码应保持同 scheme 的逻辑 commitment 输入；rooted 键集合改变的分页应明确升级 scheme 并从创世生成，不伪装成旧 scheme。

冷文件必须逐条比较返回的逻辑记录/交易定位/事件序列，保留 CRC、截断与损坏拒绝、原子发布和恢复流程；以固定缓存预算测历史点查、日志过滤、同步/冷化吞吐。仅“解压正确”不足以证明查询性能达标。
