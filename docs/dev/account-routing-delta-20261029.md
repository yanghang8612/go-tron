# 账户历史增量路由：实建及多高度 HTTP 结果

独立分页账户路由原型已在 H45,836,827 固定副本完成构建、发布及完整 HTTP
eth_call 测量。10M、15M、20M 在新增账户索引页冷缓存的两轮首查分别为
0.927–0.931 s、0.956–1.021 s、1.029–1.118 s；116/116 次请求返回预期值。
这是候选版本结果，尚未证明当前生产达到这些延迟。

产品原型源码 `78c48bd020c11dbde226cb47245ae6d3f97aaf6e`，采样及封存脚本
末端 `f31f419077bc8cc2d779a23b1839abbe73a3de47`。本轮没有推送 master、
部署、启停生产、清除生产缓存或改写 canonical 数据。

## 请求和输入

同一合约 `0xa4997124a328a4615eab437cede31da47a31b375`，calldata
`0x9fa6a6e3`，完整 loopback HTTP eth_call；9M、10M、11M、15M、20M 返回
整数依次为 207、213、220、238、249。不是多种合约/方法的总体延迟分布。

一致输入 HEAD H45,836,827，Tx 4,240,407,293，区块 hash
`0000000002bb6a1bcb3ab2e1ac8af3817bec7a121f92f1413d2552eceef0a30c`；
MuHash root 为
`4bb19b7a938ba6c865820ea86f5239235172f84923c350b04c4b0eb75743b627`。
三个表示的 canonical refs、其它辅助索引及全部前沿相同；仅账户路由有区别：

- gaps：保留原 base，但缺少此前研究确认的 1,521 个 exact pair ID。
- delta：为这 1,521 个 ID 实建 105 个独立分页增量对象。
- compact：经过 41 次有界两两合并，保留 64 个对象，仍覆盖相同 1,521 个 ID。

## 新索引冷页测试

每个高度单独启动全新只读 HTTP 进程，两轮交错测试。只将新账户增量表复制到
私有、单硬链接的新 inode，对这些自有文件执行 DONTNEED；mincore 记录证明
请求发出时这些文件的 resident pages 为零。canonical 和其它辅助表的 OS 缓存
不受控制，因此不能称为整库/整机完全冷缓存。

| 高度 | 第一轮首查 | 第二轮首查 | 两轮立即重复 |
| --- | ---: | ---: | ---: |
| 9M | 2.082086 s | 1.003657 s | 0.625–0.734 s |
| 10M | 0.930816 s | 0.927468 s | 0.580–0.583 s |
| 15M | 1.020707 s | 0.956029 s | 0.595–0.606 s |
| 20M | 1.118384 s | 1.029335 s | 0.629–0.649 s |

16/16 返回正确。不能将这一表格直接与生产公网请求相除计算收益倍数：副本

## 确定减少的实际工作

同一表示对照的 10M 首次调用，进程 rchar 从 gaps 的 206,191,356 B 降到
compact 的 86,691,314 B，read syscall 从 24,110 降到 1,886，约减少
119.50 MB 逻辑读取与 92.18% 的 read 调用。15M 为 205,814,180 →
86,314,137 B，20M 为 211,728,142 → 92,228,099 B。rchar 包括用户空间
读取计数，不能当作实际块设备物理读取字节。

实建使用分页 key/bound 表证明目标账户不在相关 exact pair 中，因此避免逐源
canonical 探测；没有将旧 base bound 直接扩展到新覆盖集合。每个增量表仅为
自身 covered IDs 提供证明，错误/缺失/预算排除继续 canonical 回退。

新增索引约 2.91 GB；这是额外辅助空间，不是回收 canonical 数据。原 base
保持原样。构建 105 批，每批 1–22 个源，总计只读取 1,521 次 source
dictionary；批次构建发布 1.176–4.142 s。41 次合并为每次 2.654–3.976 s。
软工作窗口不是严格的两秒截止；包含 ETL 和发布的完整批次可能超过两秒。

构建合计 rchar 50,436,358,193 B、read_bytes 12,993,028,096 B、wchar
20,670,630,576 B、write_bytes 20,672,425,984 B、cancelled_write_bytes
11,990,523,904 B。Linux 的取消写计数不能直接用于推算介质写入或净空间。
原始逐批 IO 在 build-result.json；本实验没有单独记录每批 CPU 时间，不能以
墙钟时间代替 CPU 证据。离线连续调用不包含 Runner 排队、负载门槛与退避，
不能作为生产补建追赶吞吐。

本轮全部原生阶段生产 PID32436、启动时间 2026-10-28 14:26:39 UTC，executable
保持 `/data/gtron/releases/auto-52aea62ef567-fcb488f6b9fdcbd4/gtron`。此前

[完整线上记录](evidence/20261029-account-routing-study/production-multiheight.json)。

本次是 reader/builder/publication 原型，**不是已经可持续追赶的生产维护实现**。
Runner 尚未接入新 family，正常路径仍有旧全表刷新；当前每请求只考虑最早
128 个相交 delta，当前 105/64 对象尚未触顶，后续增长会留下未知尾段。
合并还有单输出 256 MiB/8M 行和工作量门槛，单纯两两合并无法解决长期增长。

后续需以逻辑 run 加 key 分片控制物理大小和查询扇出，保留各 cohort 的证明
边界；增量合并可分批 checkpoint，释放重任务机会并显式 pin 输入。不能持
全局 read lease 跨整个长作业，不能因 canonical pair 更新而不断全量重来。
Runner 需切换到有界增量维护并保留 canonical merge 的公平机会，达到预算时
不能回退到旧全表刷新。合并调度探测本身也须有界，避免扫描全部 metadata。

热 history 未索引尾部仍是独立瓶颈；在维护、尾部和实际生产首查均确认前，
整体首次冷查优化目标继续保持进行中，不能用本次副本达标关闭目标。
