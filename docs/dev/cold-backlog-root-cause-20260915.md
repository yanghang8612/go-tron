# 冷历史积压根因与固定输入验证

截至 2026-09-15，线上完整冷维护速度低于历史区块导入速度，积压尚未解决。
本次优先验证减少冷构建的实际工作与增加安全并行度；不把入口限速或分配下降当作吞吐修复。

## 真实范围与数据分布

停服后以只读 Pebble 和一个固定快照采集 30,975,118–30,975,133，共 16 个完整块。
整个停启、采集、恢复健康检查事务约 41.7 秒，其中物理采集约 2.2 秒。
原生产二进制 `7b2b374a` 已恢复；这些数字不是服务不可用时长的单独测量。

采样保留原始键、shared pack 和 chunk 编码，并验证 canonical/tx-range 绑定。
物理导出完整不等于逻辑内容认证；后续离线回放另行完成全部认证及 hot/cold 逐行比较。

| 指标 | 本次范围 |
|---|---:|
| 物理行 | 283 |
| 物理键和值 | 13,192,384 B |
| 声明的历史展开量 | 101,902,854 B |
| shared 引用 / 唯一 chunk | 2,064 / 234 |
| 逻辑历史记录 | 9,163 |
| 完整 Prev 字节 | 101,515,932 B |
| 至少 128 KiB 的 Prev | 49 条 / 100,937,974 B |
| 最大单个 Prev | 4,361,457 B |
| SystemDelegation 域 Prev | 159 条 / 100,955,543 B |

进一步按逻辑键族完整解码，旧版资源委托聚合列表 `drax-0` 共 98 条历史行、
100,940,178 B，占全部 Prev 的 **99.433%**。其中全部 49 条大旧值来自仅 **2 个不同逻辑键**；
最大版本包含 198,243 个 to 地址、3 个 from 地址。87 条存在的旧值合计展开 4,587,949 个
to 引用，包含重复历史版本，不能当作独立地址数。其余 delegation 键只有 15,365 B。

这证明问题集中在高扇出旧版委托列表的反复全量版本上。物理去重已将相近内容存成
shared 引用，但冷构建仍展开这些引用，
校验各 chunk 和完整 pack，并重新生成带完整 Prev 的冷记录与 CDC 容器。

## 原生完整构建对照

诊断源码 `e3a7bf49525ec293d25a9403d0ce0372b93dd961`，原生 Go 1.25.5、Linux/amd64、
`GOMAXPROCS=2`、压缩策略 `auto`。A/B/B/A 每次三个构建，模式各六个样本。
所有三件套的字节与引用完全一致，完整逻辑 digest 相同，采样文件前后未变。

| 模式 | 16 块构建墙钟中位数 | 按该中位数折算块/秒 |
|---|---:|---:|
| 原防御性二次拷贝 | 2.1067 秒 | 7.5949 |
| 已声明独占 Get，省去二次拷贝 | 2.0204 秒 | 7.9192 |

墙钟下降 **4.10%**，不足以解决持续积压。这是缓存已热的私有源、完整冷三件套构建；
不含生产 LSM 布局、全清单发布、裁剪、合并及维护恢复等待，不能当成线上持续冷覆盖速度。

独立的 owned 构建 profile 共 2.15 CPU 秒，其中 SHA-256 的 AVX2 实现占 1.64 秒
（76.28%）。服务器 `/proc/cpuinfo` 显示 AVX2、AVX512F 可用，未暴露 SHA/SHA-NI。
先前生产 45 秒 profile 中，冷构建调用树同样主要消耗在 SHA；两份 profile 不拼成同一窗口。

## 完整服务与硬件边界

02:54:22–03:00:22 UTC，同一旧进程的六分钟窗口：导入 19.5725 块/秒、冷覆盖
4.7718 块/秒，可归档积压增加 5,320 块。04:04:43 UTC 的恢复后单点可归档积压为
1,065,967 块；这个单点不是新的测速窗口。

03:08:39 UTC 的独立资源窗口中，16 个逻辑 CPU 的总空闲约 53%，同时数据设备很繁忙。
CPU 总量未耗尽，不能据此断言必须换硬件；设备繁忙也不能证明已经触及未查明的 EBS 配额。
SHA 指令缺失是已确认的硬件条件，换机收益仍需相同真实输入验证。

## 分段并发的结果与否决理由

原生源码 `3fd7eeddfd9889ab33e167a16d04f588d6175962`，固定相同的 16 块，
`GOMAXPROCS=4`、owned Get、auto 压缩，六配置正序、逆序各一次，全部完整认证通过。
合计 ETL spill 配置阈值为 64 MiB，非 RSS 上限；每 worker 阈值随并发数变化。

| worker / 段数 | 全组墙钟中位数 | 按中位数折算块/秒 | 全组输出 |
|---|---:|---:|---:|
| 1 / 1 | 2.0734 秒 | 7.7170 | 12,421,391 B |
| 1 / 2 | 2.0769 秒 | 7.7038 | 17,330,016 B |
| 2 / 2 | 1.1535 秒 | 13.8705 | 17,330,016 B |
| 1 / 4 | 2.1518 秒 | 7.4357 | 27,350,568 B |
| 2 / 4 | 1.1076 秒 | 14.4452 | 27,350,568 B |

同分段数量下可见并发收益；跨分段则同时改变字典、压缩选择、去重范围与输出量。
四段输出增加 120.19%，且 18.28 块/秒仍未包含清单发布、裁剪、合并及恢复等待。
只有每配置两个样本，不能拿该数字承诺持续吞吐。**本次否决直接上线分段并发**，
避免增加小段、冷输出与未来合并负担。后续优先测试单三件套内部流水线。

## 单文件两任务流水线的原生结果

`GOMAXPROCS=4`，A/B/B/A 各三次构建，每模式六个样本；另外各一次 profile 不计入中位数。
完整认证、每行内容、三个文件的 refs/字节完全相等，输出保持 12,421,391 B，输入前后不变。

| 模式 | 16 块墙钟中位数 | 按中位数折算块/秒 |
|---|---:|---:|
| 串行认证 | 2.0010 秒 | 7.9958 |
| 两任务认证流水线 | 1.4423 秒 | 11.0942 |

墙钟减少 **27.92%**，但仍不足以在额外发布、裁剪、合并和恢复等待后消化约 20 块/秒导入。

## 消除冷分块重复摘要的原生结果

`51482c56582fa0b93ccbf5b22bb9f1c80aff96c2` 对仍在当前字典中的候选先完整比较字节，
完全相等才复用已有 SHA；首次/不等/快速指纹碰撞仍走原 SHA 计算。未更改输入认证或文件格式。
两固定二进制 8ddc→51482 的 A/B/B/A 每组三次构建，固定 owned/auto/串行读/GOMAX4，
每版本六个 primary 样本及一次独立 profile；所有 trios 的字节、refs、完整 digest 均相等。

| 版本 | 16 块墙钟中位数 | 按中位数折算块/秒 |
|---|---:|---:|
| 原 CDC 摘要路径 | 1.9982 秒 | 8.0071 |
| 完整相等后复用摘要 | 1.7679 秒 | 9.0505 |

真实完整构建墙钟减少 **11.53%**，输出仍为 12,421,391 B。它也用于合并中的同一 writer，
但此实验没有直接测完整 merge 和线上维护，不能按相同百分比承诺其收益。M1 合成低复用数据
测得约 3%–5% 的额外开销，必须保留这一适用范围限制。后续将单独测量固定读取/压缩并发下

## 修复方向与限制

先比较相同总输入的有界并发构建，分别统计速度和输出量；增加小段会影响压缩率、
清单数量及后续合并，不能仅看构建提速。优先验证单个冷三件套内部的按块并行认证、
有序消费，保留两遍扫描和原输出格式，以解码字节与任务数共同约束在途内存。

若仍不足，需要改变历史的物理表示，使大旧值不再重复展开、重新切块与哈希。
自包含的冷引用容器或有界 checkpoint 加增量必须有完整 reader、索引、合并、
裁剪证明、崩溃恢复和新旧双读。不能永久引用随后会被热 GC 删除的 chunk。

只拆分当前 delegation 列表的存储键，无法自动消除已经保存的百万块旧积压。
直接提前切换 proposal 69 的关系键还会改变历史链上行为；物理改造必须保留相同逻辑值、
顺序、存在性、交易版本与 commitment。旧 pack 至少仍须完整认证一次。

本地原始数字与命令记录位于 `build/benchmarks/20260915-root-cause/`；原生采样和
完整报告位于 `/data/gtron/releases/20260915-history-range/result/`。设计约束见
[固定范围与并发方案](../superpowers/specs/2026-09-15-cold-throughput-root-cause.md)。
