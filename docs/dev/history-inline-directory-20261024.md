# 单次变化内联与目录查找：离线验收

范围：只在独立工作树和不可变副本上实现、验证；不推送、不部署、不重启线上节点，不改线上目录。

## 实现

`.kv` accessor 升至独立 V8 格式；`.seg`、`.idx`、最新状态表和 MuHash 元素编码不变。字典键、key ID、字典 SHA256、交易顺序、before-image 内容均不变。单次变化的 TxNum 差值、逻辑位置、记录序号移入受 CRC 保护的键页，省去外置 posting 的标记、独立 CRC 和位置引用；多次变化仍采用原有 V7 分帧字节。

“单次变化”指同一个段中该键只有一个 posting，不代表整条链只变化一次；键数量按段内实例累加，不是跨段去重后的全局唯一键数。

目录每 32 个键页增加一个稀疏定位项，根和单个目录组各限制在 64 KiB。点查验证稀疏根和选中目录组后读取键页，避免原有多层二分查找的小块随机读取；小目录一次读取。没有新增跨请求的未认证缓存，超出边界使用原有路径。严格导入仍检查完整文件及字典、目录、posting 语义。

旧读取器不能读取 V8。本次没有线上转换或启动时迁移；未来发布、回退需要单独处理已有 V8 文件。

## 对照输入与边界

1. 空间：`/data/gtron/kv-accessor-analysis-20261024-01` 的原冻结 cohort，19,949 个 V7 `.kv`，文件长合计 154,037,203,799 B。逐文件验证原清单 SHA，向独立 inode 写出 V8、重新读取，比较所有键、ID、单次变化元组及多次变化字节。这份 corpus 不是完整可恢复节点，不能用来声称其高度的 HTTP 已验收。
2. HTTP / MuHash / 恢复：沿用完整 11,818,192 高度副本，交易序号 601,386,177，MuHash `8fbf149684146a59b1650b318a768f0edbae0c8c1c3ceb2c5c610129c10f76a5`。基线和候选均由同一物理冻结输入派生；候选只替换 accessor，辅助路由 source ID 随物理 SHA 改变后重新绑定，并对路由成员关系做严格重建核验。
3. 基线生产源码为工作树 `9ed8b4bd`（非测试 Go/Rust 与 `43c3d47b` 一致），不是当前线上 `9a67678a` 的性能归因。1,074 个基线源码文件逐个 SHA 对照；新旧 HTTP 测试宿主相同。所有请求走 loopback HTTP → JSON-RPC → TronBackend → TVM，未启动同步、P2P、冷发布或清理。
4. 调用合约 `0xa4997124a328a4615eab437cede31da47a31b375`，数据 `0x9fa6a6e3`，覆盖 3,144,020、3,144,021、5M、9M、11,817,936、11,818,191、latest。预期分别为 6、7、63、207、225、225、225，依据原完整 before-image oracle，逐次核对完整返回值。
5. 热缓存、全新进程、独立 inode 的 OS 冷缓存分别统计，交错新旧执行顺序。OS 冷样本只对独立 inode 执行 fadvise，并用 mincore 核对驻留比例，不清理全局 page cache。小样本仅报告中位数和范围，不据此宣称生产 p95。
6. 快照恢复核验在三个 20 块窗口实际恢复、读回，对比原 full-row 流 SHA，共 22,496 行和 60 个交易范围；另有包级快照/导入/恢复回归。MuHash 只覆盖最新 canonical 状态，不能单独证明冷索引正确；冷历史由全键/元组比较、多 posting 字节比较、HTTP oracle、实际恢复读回及伪造元组拒绝测试另行核验。不能将窗口恢复描述为 11.8M 的全量快照导出/导入。

## 结果

完整测量及最终复核已结束。候选 19,949 个文件重新 fsync / 全量 SHA 复读通过，所有文件均比源文件小；本地重新汇总所有文件计数及 HTTP 资源指标，与服务器回执一致。

测试期间生产节点在 2026-10-24 05:57:01 UTC 被外部操作更换二进制并重启：PID 5408 / `d8e24fc5…` → PID 27692 / `7e4e5dfd…`。本实验没有操作生产服务。热缓存和全新进程测量在 05:46–05:48 UTC，独立 OS 冷缓存测量在 05:57:39–06:06:59 UTC；前后背景负载不同。各阶段内部仍为同一冻结输入、同一对测试二进制，交错 A/B，但不能跨阶段计算优化倍数，不能据此归因当前线上版本。原 identity assertion 因此失败，保留失败回执及 systemd 事件，并单独记录环境变化，没有重复或替换任何计时样本。

诊断步骤第一次运行 `go tool pprof` 时因瞬态 systemd 环境没有 `HOME/GOCACHE` 退出；补齐 Go 构建缓存路径后用原 profile 生成报告，再补齐候选和最早高度诊断。这个错误不属于 HTTP、MuHash 或历史恢复失败；原日志完整保留。

## 正确性和测试

- 每个转换文件比较所有 key、key ID、字典 SHA、单次变化三元组，逐字节比较全部多 posting，重开候选读取，并检查严格字典/路由成员覆盖；没有以文件长度代替语义验证。
- 完整副本扫描 144,903,091 个物理行并重算 canonical MuHash 通过；扫描行数按源分别 3,484,117 / 481 / 141,418,493，根与固定输入一致（物理扫描行数包含失效 generation，不能视作全部参与 MuHash 的 canonical 元素数）；耗时 1,025.03 秒。
- 实际恢复三个 20 块窗口（3,144,020、5M、9M），恢复并读回 387 / 11,845 / 10,264 行，总计 22,496 行和 60 个交易范围；与原 full-row 流 SHA 一致，耗时 73.40 秒。
- V8 单/多次混合、129 条分帧边界、空/边界、目录 CRC/覆盖/排序、内联边界、取消及伪造 ordinal 的联合导入拒绝测试通过。伪造测试重新计算 CRC/文件 SHA，仍由历史语义覆盖核验拒绝。
- 本地和服务器 Sapling 环境的 rawdb、state、snapshots、core、CLI 五包完整测试均通过；相关 race、vet、服务器构建通过。包内历史查询、流式构建、合并、导入导出及恢复回归通过。
- 有界目录 fixture 的原始 `ReadAt` 次数为 V7 16 次 → V8 4 次。这只证明指定点查的系统调用减少，不代表完整 HTTP 提速四倍。

## 剩余瓶颈和后续方向

9M 候选 CPU profile 中 `PrefetchExecutionAt` 累计 79.09%，其中热尾分支 `iterateOwnerLocked` 累计 48.07%，`iterateHistoryOwnerSpans` 44.00%；冷查询分支 `FirstStateDomainChangesContext` 累计 30.13%。这些是调用树累计占比，有父子重叠，不相加。与基线对应的 46.94%、44.08%、30.28% 接近。Snappy 解码平坦样本 17.64%，SHA256 AVX2 12.98%，Blake2b AVX2 13.38%，说明数据解码、完整性/身份哈希与段选择仍占明显 CPU。目录减少小读取没有消除这些工作。

源码与 profile 一致：`core/rawdb/state_history_owner_spans.go` 的 owner span 路径仍先对完整 pack 计算 Blake2b，再 materialize / Snappy 解码完整 payload，之后才按选中 span 做两遍验证/输出；因此 owner 行范围索引没有消除整包解码。`latestSegmentRef` 仍逐项扫描当前 manifest，目录查找优化不覆盖它。不能把这些未改动开销算作 V8 新增成本。

对请求前后两次 `/proc/self/io` 标记之间的 strace 做逐线程 unfinished/resumed 拼接，9M 首次请求的数据库读取为 1,869 → 1,832 次；其中 `.kv` 95 → 58 次，而 `.sst` 两侧均为 1,704 次、15,738,286 B，`.route` 均为 9 次、4,726,295 B，`.seg` 均为 59 次、1,325,060 B，ancient `.gtv2` 均为 2 次、572,504 B。它们是逻辑成功 read/pread 的请求窗口统计，不是块设备实际读量；trace 样本不纳入 HTTP 延迟。大多数首次读取来自 Pebble SST 和辅助路由，而非本次压缩的 accessor。

这支持下一步优先检查热尾 owner span 的候选范围、跨请求可验证元数据复用、冷查询中的段引用选择和重复完整性检查；对于 OS 冷请求，再根据请求窗口内 `.sst`/`.seg`/`.kv` 读取拆分决定 read-ahead 或数据布局。任何复用都需要与不可变 source ID、manifest generation 和生命周期绑定，保留未命中/损坏时的权威路径；不能直接省略校验或复用其他 generation 的负结果。以上为后续方向，本次未实施这些额外改动。

当前结论是 **V8 空间收益已证实，目录点查的读取次数减少，但完整 HTTP 延迟没有证明改善，最早高度热缓存还有一组回归样本**。本次保留为离线实现和验收，不推送、不部署。
