# V5 历史页有序并行编码

当前为已通过本地检查、尚待原生固定副本实测的候选。默认 `auto` 不变，
没有推送、部署、启停生产服务、删除数据或调整生产资源参数。

上一轮 `0071ef14` 已将每组多余的约 1.25–1.32 GB 累计内存分配消除，
但真实冷发布仍比 V2 慢 53.52–68.17%。三组实际合并的 CPU profile 显示
Zstd EncodeAll 累计 CPU 为 1.91→6.21 s，ETL loadRows 均为 3.52 s；V5
强制串行编码，V2 则在 1 MiB 后使用有序页流水线。原始 profile 和可重复
核验见 [上一轮报告](history-columns-encoder-reuse-20261026.md)。

本次格式 5 使用已有的压缩线程预算，大输入在相同阈值后进入有序流水线，
最多四个线程，最多 `2 × workers` 页在途。每个线程独占编码状态，仍比较
普通压缩和三种键编码，严格选择更小者。物理格式、128 KiB 解码单元和
还原依赖不变，目标是保持输出字节和压缩率。

两处关键归属修正：记录位置列表在入队时复制，获胜压缩缓冲移交结果后从
工作线程脱离，直到有序落盘完成才回收。页起点由写入器自身的逻辑位置计算，
不再读取异步 reducer 更新的 `body.uncTotal`。切入并行后释放串行编码缓冲。
Reset、Abort、取消及错误均等待线程和 reducer 结束。

本地六项检查已全部成功：实际 compactor 大输入夹具、定向测试、rawdb /
state / snapshots / core / cmd/gtron 五包完整测试、race、vet、Sapling
构建。1、2、4 线程（请求 64 时限制为 4）及不同 Write 分片生成的完整文件
逐字节一致，覆盖跨页大值、部分记录头、普通页、前缀回填和 Reset。额外测试
验证排队结果不被后续编码覆盖、记录位置不被借用、满队列取消、写入错误和
非法页不发布目标文件。真正 compactor 夹具中串行/并行 V5 的三件套引用相同，
与 V2 的规范字节及伴随索引摘要一致。

四线程压缩缓冲的保守容量上界为 **5,992,408 B**（约 5.71 MiB），包括
页/结果池、每线程临时缓冲、记录位置、保留前缀和已有的 body bufio。
实测单线程私有工作缓冲 575,079 B。该上界不包括已有 Zstd 引擎、ETL 和
块目录，不代表进程 RSS；没有提高生产内存/CPU 配额。

首次独立记录位置测试把临时文件的 48 字节物理头也计入了页编码对照，修正
夹具范围后通过；失败原件和后续成功日志都保留，未改变编码选择来通过测试。
