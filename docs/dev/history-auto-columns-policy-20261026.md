# 自动分列压缩策略：隔离实现

新增显式 `--history.compression-format=auto-columns`，用于普通 V6 新建段和
合并段选择 128 KiB 分列，同时保留原有 CDC 自动选择。默认仍为 `auto`。
本阶段只在独立本地工作树实现和测试，没有推送、部署或操作生产服务。

## 选择与数据边界

- 生产 V6 构建仍在原字典键收集过程中观察相同的有效记录。重复大旧值满足
  现有有界策略时选择格式 3，其他情况选择格式 5；阈值、键内存上限及
  Prev 所有权不变，不增加旧值扫描。
- 自动合并沿用原有源头部读取。任一输入为 CDC 时保持格式 3；其余输入在
  `auto-columns` 下选 5，在 `auto` 下仍选 2。
- 无行信息或注释的旧流式入口保留原 `auto` 的 V2 回退。既有文件的迁移
  兼容性判断与 `auto` 相同；不能把选择新写入策略说成既有文件已变小。
- 继续使用现有格式 3/5 的 reader、规范字节和索引认证。没有增加物理格式，
  没有更改 MuHash 元素、历史值、逻辑 offset、序号或恢复协议。

新写入策略不同时生成完整的 2/5 两份文件做整文件择优；离线转换器的
“整文件无收益则保留原文件”不能移作这里的保证。格式 5 仍按页选择普通
压缩或分列，标记等开销必须计入净空间；CDC 也沿用已有启发式，不增加
旧值相似度扫描。实际净收益和写入成本仍需完整副本及代表性负载验证。

## 验证进度

已通过初轮针对性测试：普通数据和重复的 512 KiB 不透明旧值、生产建段、
真实无序热数据的 ETL 外排回退、`2+5`／`5+3`／`3+5` 实际合并及历史恢复。
比较独立热／冷摘要与规范 V6 原始编码，而不只检查物理格式号。
CLI 优先级、独立诊断和 2/4/8 reader slot 的单 trio 字节对照也纳入检查。

审查随后发现通用 footer 校验入口遗漏新名字。只中断本机已确认归属的
检查进程组，保留初轮日志和源码指纹；补齐入口及完整压缩 blob 回归后，
重新执行本地完整相关包、race、vet 与 Sapling 构建，最终均通过。
完整五包耗时 582.505 秒，针对性 race 35.167 秒；检查期间 2,146 个
Go/module 文件及复用的 Sapling 库指纹未变。
[完整记录与只读复算入口](evidence/20261026-history-auto-columns-policy/README.md)
包含全部改动源码、日志、初轮中断记录及明确区分的旧实验状态。
