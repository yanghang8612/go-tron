# 9M / 10M / 15M / 20M 全 HTTP 冷查及热尾验证

本轮在固定副本完成覆盖补建、热尾候选实现和完整 HTTP 对照。所测请求没有重现几十秒延迟，返回值全部一致。但新增热尾方案没有稳定净收益，重复查询反而慢约 11%–15%，因此性能验收结论是 **暂不合入 master、不部署**。本任务没有执行生产服务启停、删库或格式回退。

固定切面 H=45,836,827、Tx=4,240,407,293，MuHash HEAD root 为 `4bb19b7a938ba6c865820ea86f5239235172f84923c350b04c4b0eb75743b627`。所有 A/B 使用同一套 canonical 数据；辅助索引状态按阶段分别记录，不能混算不同阶段的样本。

账户冷源覆盖从 30,539 / 32,036 补齐到 **32,036 / 32,036**，修复 1,497 个 exact source，耗时 496.574272486 秒，另做 8 次有界 delta 合并。canonical refs、frontiers 和 commitment HEAD 未改变。这是副本结果，不能当作生产已经补齐。

原固定副本的 posting 前沿实际已经等于 HEAD。先测该状态，再仅在私有副本降低派生 posting watermark 到 45,835,409，恢复历史原始的 **1,418 块**未索引尾部。每块 encoded canonical pack 的存在性、长度和 SHA256 均已记录；原始 postings、history rows 和冷段保留。另有独立标注的 256 块试验，未与 1,418 块数据混算。

冷缓存口径：逐版本 trace 完整启动和四高度 HTTP，覆盖 chaindata/history/ancient/state-snapshots，确认没有数据库文件 mmap；将 HTTP 实际读取的完整文件换成独立 inode，再对这些私有文件 fsync/fadvise。每个新进程启动前和 HTTP 发出时，逐文件 mincore 必须为零；HTTP 出现未纳入文件即拒收并扩展读取集合。最终集合 1,598 个文件、26,623,043,066 B。保留服务启动必需的内存元数据缓存，计时包含完整本机 HTTP，排除进程启动和公网代理。没有清空生产共享页或设备缓存。原 all-open 方案包含 482 GB 的 ancient 启动文件，其复制被终止，未作为性能结果。

完整请求为 `eth_call`，合约 `0xa4997124a328a4615eab437cede31da47a31b375`，data `0x9fa6a6e3`。9M/10M/15M/20M 的 uint256 返回分别是 **207 / 213 / 238 / 249**；本地独立复核了完整 32 字节 result、RPC id 和 JSON-RPC 版本。

本轮最终矩阵共 24 个 HTTP：8 个带 trace 的发现请求排除计时，8 个冷首查和 8 个重复全部通过。冷查单样本显示 10M/15M 有改善，9M 持平、20M 变慢；不计算 p95，不宣称整体加速或任意查询绝不会超过几十秒。

作为另一个独立阶段，posting 已追平状态下，`0f93254` / `87260ebc` 两版各做四高度两轮，候选冷首查范围 2.33628–2.63805 秒、重复 0.57044–0.64673 秒。该组确认索引追平时不存在几十秒延迟，但不能用来证明新热尾方案收益。

本轮依次试过：有界完整键目录、V4 固定 Bloom、请求内过滤器缓存、独立小记录、完整范围合并。保留所有负收益结果。完整键目录超过上限会反复回退；Bloom 消除了上限缺口，却多次读取/校验大 owner 目录；拆出小记录后仍有多家族 seq-zero 扫描。最终按完整连续范围复用阴性证明，深拷贝全 owner positive-seq repairs，限制 1 MiB，并对计划账户逐包记录阴性探针，避免 OR 饱和消除证明。未知/损坏/缺包/早停/取消/预算溢出均不发布完整范围。

诊断发现进程中，四个请求的 pack-filter 尝试从 22,688 次降至 5,672 次，即每请求只扫描 1,418 包；其余账户、DP、fork 家族均命中范围摘要。算法确实减少了重复扫描，但旧 owner-plan cache 本来也有复用，因此没有形成稳定的完整 HTTP 收益。9M 重复查询两版仍各读取 88,916,742 B；首次物理读取原路径 215,830,528 B，新路径 224,768,000 B。不能只据扫描计数宣布成功。

剩余更大的目标是系统旧 broad route：独立 syscall 分布记录中，每次查询读取同一个 66,948,766 B 的 `system-routing-1-3006279261-…route`。应优先完成相应轻量/metadata 路由覆盖或改为绑定 manifest 身份的按需读取与有界认证缓存，再比较净 HTTP 收益。生产应继续保留已验证的 owner-plan 路径；当前实验分支不满足直接合入门槛。新写入侧还存在一次 owner 目录重新解码来导出小记录的成本，后续若保留此设计，需要让 builder 一次产出两个值并补测导入开销。

正确性验证包括 rawdb 全包（25.894 秒）、定向 race（3.382 秒）、vet，以及快照恢复/账户 delta MuHash/已验证 catalog 的定向回归（2.203 秒）。所有原生 ready receipt 的 HEAD/Tx/root 一致，没有反复扫描全库 MuHash。Astra 只读复核指出的取消发布锁等待边界已追加修复及定向 race（2.944 秒）；该收尾改变只影响取消请求，没有重复正常请求的原生矩阵。

原始 ZIP 均已下载并核对服务器回执 SHA256，再独立复算返回值、trace、私有 inode/读取闭包和零驻留页。摘要及精简原始请求在 `evidence/20261029-whole-query-cold/`；大 trace 在本工作树 `build/benchmarks/20261029-whole-query-cold/`，ZIP 保存在本机 Downloads。最终归档为 `AAA-gtron-http-tail-1418-filter-range-20261029-final.zip`，3,286,023 B，SHA256 `edf2e7a1c5e69b6bf4e486d0b5ddf4ee8338e300921c8ef2de828ff7bb715753`。
