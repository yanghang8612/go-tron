# 128 KiB 记录分列容器：集成验收进度

本阶段只修改本地候选代码和独立固定副本。不发布、不启停线上服务，
不删除旧数据；默认 `auto` 和已有显式格式的写入选择保持原样。

## 已完成的本地实现

- 显式物理格式 `5` / `gtcend05`，逐页选择普通 Zstd 与三个 HRC2 键模式中的最小结果。
  页内独立还原，规范 V6 字节、记录位置和逻辑索引保持一致；没有跨页还原链。
- 单页最多 128 KiB，沿用 16 页缓存，转换缓冲复用且有界；限制压缩输入、
  Zstd 输出、记录数、列长度和整数运算，返回前验证规范页 CRC32C。
  原有文件 SHA256、伴随文件和路由认证仍适用。
- 覆盖正常、借用、流式、ETL 回退和合并写入的记录头标注；支持 Reset、取消、
  跨页记录头及大旧值。只保留有界偏移，不保留借用的账户／旧值缓冲。
- 离线三件套转换器先验证原文件，再完整比较规范字节、严格验证新三件套。
  无净收益时保留原文件。接口本身不发布 manifest、不变更路由、不删除源文件。
- 补齐读取、诊断、迁移识别、业务抽样、预算和 CLI 格式校验入口。

## 采用策略的新增限制

对固定副本全量读取头部，4,609 个原始 `.seg` 全部为物理格式 2。
UTC 18:36:28 已完成的 1,631 个文件全部选择新格式，整文件回退数为 0。
因此上述部分收益没有混入 CDC 文件，也没有依靠保留原文件筛选有利样本。
此结论只覆盖该固定副本，不能推断更高高度的 CDC 分布。

本地增加 16 个重复的 512 KiB 不透明旧值压力用例。真实构建与严格读取后，
完整三件套的长度分别为：普通格式 2 的 8,393,548 B、CDC／`auto` 的
2,409,637 B、显式格式 5 的 8,393,614 B。所有逻辑行和交易区间摘要一致；
离线转换正确保留原 CDC 三件套。这个反例证明：**不能因离线选择性转换
有收益，就从创世一律强制格式 5。**

现有 `auto` 在键遍历中执行有界的大旧值策略，合并时也保留 CDC 选择。
显式格式 5 不执行该策略。若完整验收支持采用分列，应增加单独的自动分列
策略，保留 CDC 判断，再让普通段选择分列；本阶段尚未实现该策略，默认
`auto` 未改变。压力用例不是主网分布或 HTTP 测量，不据此推算线上退化倍数。

## 尚未完成的门槛

3. 新候选完整 MuHash 重算、冻结 chaindata 前后指纹、实际历史恢复与快照边界检查。
4. 同一固定副本的完整 HTTP `eth_call`：热缓存、新进程及独立 OS 冷缓存，
   对齐二进制、资源、请求和返回值。抽样页 CPU 结果不能代替此项。
5. 冷发布吞吐。当前每页最多编码四次，写入侧仍可能增加 CPU 成本；实测前不判断可上线。
