## 调度改变

small、metadata、storage、account 轮转；每三个实际辅助操作后仍保留一次
canonical 合并机会。账户任务最多尝试 64 个源，声明 accessor 输入上限
128 MiB，源间软工作窗口两秒；单输出仍限 256 MiB/8M 行。ETL、写入和发布
计入完整操作耗时，所以完整批次不承诺两秒截止。

Runner 保存游标、旧范围输入指纹、未解决洞、退避状态。纯尾部追加不会不断
解除失败前缀退避；内部源替换会重新扫描；不支持源只推进调度位置，不产生
absence proof。硬错、取消和发布冲突不推进已尝试游标。无产出但已读 metadata
或 dictionary header 的批次也消耗一次机会，不能堆叠后续大路由任务。

发布只保护本次输出范围，因此另有回归覆盖“构建 B 期间已扫过的 A 被替换”：
发布后排除自身新增对象，比较前后范围指纹；其它变化强制立即重扫，不把新 A
吸收进指纹后越过。损坏或缺失的旧辅助 metadata 作为 unknown，仍计预算，
让健康 canonical 字典继续补建；canonical 文件错误继续传播。

全包测试曾发现小库启动时过早补建会改变常规合并顺序。本轮恢复原启动门槛：
至少 64 个冷 history 源，或已有账户 base/delta，才开始账户维护。随后原失败
用例及全包均通过，没有放宽合并测试的断言。

## 查询选择及 CPU 边界

不可变 manifest 懒加载区间树，仅保存 row number 和 subtree max ToTx，
每个对象 12 B、独立最多 3 MiB；不缓存文件内容或 absence proof。
实际源进入查询时，仅访问能完整包含该源的对象，再认证 metadata/页和 exact
pair ID。128 上限限制本请求实际尝试的对象，而非按 manifest 顺序截断尾部。

对象、metadata 或驻留预算耗尽后，只检查最多 128 个已尝试 proof，停止遍历
其余重叠区间。回归用 4,096 个同范围对象反复查询，限制总 tree callback 为
129 次，并确认缓存的合法 proof 仍能使用；预算排除或不可读对象保持 unknown。

4,096 个互不重叠包络的合成查找 microbenchmark：线扫 2,690 ns/op，区间索引
127.2 ns/op，两者均零分配。它仅衡量包络选择，不是完整 HTTP 倍数。
