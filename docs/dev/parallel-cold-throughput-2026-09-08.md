# 多核冷化吞吐优化

本轮目标是让历史冷化持续快于同步，减少正在增长的积压。沿用完整历史和现有文件格式；不删除任何历史版本，不重建当前数据库。

## 改动及原因

- 正文 V2 以完整压缩帧并行 Zstd/CRC，最多 8 个 worker，读取、protobuf 变换和落盘保持顺序。原始输入队列最多 64 MiB，复用缓冲另有 64 MiB；再加生产者当前帧、压缩结果和 encoder 工作区。超大帧排空队列后单独处理，因此这些限额不是整个进程 RSS 上限。
- 事件 V4 payload 采用最多 8 个 worker、按原序落盘，在途 raw/encoded 预算 8 MiB，超大行保留同步路径。构造 payload 时直接投影 Data 和 unknown 字段，减少先 Clone 再删除地址/主题的复制；protobuf schema 扩展时退回原通用投影。
- 事件两遍构建之间复用已验证的块和交易哈希，缓存收费上限 32 MiB / 65,536 块。第二遍仍从 ChainDB 重读完整正文并校验 SHA-256，严格检查 receipt 数量、块号、ID；缓存满时退回原解码路径。不会依赖可变正文缓存，也不额外写一份正文 spool。
- V6 首遍逻辑 key 收集增加精确去重，最多 65,536 条 / 16 MiB key 字节；低命中输入试运行 4,096 次后退出。ETL 仍完成跨缓存重置的排序和去重，所有 posting 和旧值保留。
- throughput 在新鲜引擎及设备观测、无硬压力、恢复/健康等级且 await ≤ 2 ms 时采用 80%/90% 历史目标占空比，默认短恢复下限降为 250 ms。未知、过期、压力及较高延迟沿用原预算；明确设置的更长恢复期、失败退避和既有截止不缩短。仍按完整批次时间/输出字节调节范围，仍通过共享重任务准入。

## 固定输入基准

本地 Apple M1 Max，Go 1.27.1。正文比较 GOMAXPROCS=10；事件和 key 比较 GOMAXPROCS=4。表中为三组结果中位数，fixture 各不相同，收益不可相乘。

| 实验 | 原路径 | 新路径 | 范围 |
| --- | ---: | ---: | --- |
| 64 MiB 正文写段，1→8 worker | 419.87 ms | 148.87 ms | 2.82 倍吞吐，输出均 24,294,184 B |
| 三表完整 Migrate，1→8 worker | 541.34 ms | 245.19 ms | 2.21 倍吞吐，输出均 32,443,879 B |
| 16 MiB 事件 payload 的完整构建，1→4 worker | 90.50 ms | 69.00 ms | 耗时减少 23.8%，输出相同 |
| 事件两遍身份复用，固定单压缩线程 | 127.86 ms | 80.50 ms | 耗时减少 37.0%，输出均 141,672 B |
| 重复 key 首遍 ETL，262,144 次/1,024 唯一键 | 21,233,664 B 输入 | 82,944 B 输入 | 少 99.61%，字典相同 |

完整 Migrate 包括三个表、逐帧校验、fsync、manifest 发布及 live install，但输入是确定性内存数据，未包含真实 Pebble 读取及 protobuf Source/Transform。其累计分配从约 251 MB 增到 489 MB，是用内存和 CPU 换吞吐，不能当作峰值 RSS。事件身份复用 fixture 是真实 MemoryChainDB 96 块 × 32 交易，含合成合约调用及无日志交易；累计分配约 49.11→37.99 MB。

原始结果在本地 `build/benchmarks/20260908-freezer-pipeline/` 与 `build/benchmarks/20260908-cpu-cold/`。上述实验不是主网吞吐承诺。

## 正确性边界及验证

测试覆盖完整文件/索引 checksum、全量及地址/主题查询、全部压缩 codec、borrowed buffer、乱序完成、编码/写入/源读取错误、取消后 worker 清理、超大帧、缓存双限与低命中回退、源正文变更及收据损坏拒绝、genesis 特例。

真实 ancient 回归同时覆盖 V1 文件和 V2 compact 后 V1 已回收的来源：删除全部测试热正文/收据，确认热行不存在，再执行两遍身份缓存构建；正文及索引 checksum 与热源基线一致，查询通过。完整校验、fsync、manifest 与热删除顺序没有改变。

全仓初验指出两处读取边界白名单需要跟随实现更新。已明确登记接受 `*ChainDB` 的身份验证适配器，以及拥有原覆盖检查的内部 worker 构建函数；未关闭或放宽全局审计，`scripts/dev/audit_hot_only_reads.sh` 复验通过。最终 `go test ./... -count=1 -timeout 300s` 通过：54 个有测试的包、13 个无测试的包、0 失败。最终相关 snapshots/freezer 定向 race 也通过；原生部署结果在后续验收记录中追加。

## 线上基线

同一旧进程 11:06–14:57 的近四小时记录：同步 63.58 块/秒，冷化 56.07 块/秒，积压扩大 103,855 块。部署准备期 15:20–15:25 的短窗口则为同步 74.59、冷化 89.05，距离缩小 4,338 块，说明负荷及后台阶段有波动。上线后必须使用包含正文转换的连续窗口衡量，不能只挑选有利区间，或把不同高度的结果称为同输入 A/B。
