# ContractStorage / SystemShielded 精确分布与格式优化分析（2026-10-19）

**建议先做 Storage 数值紧凑编码，再将 Shielded 的逐块根索引改为变化点；缩短 Storage 键可一同完成，但单独收益较小。** 用户已明确允许不兼容本地格式及未来从创世同步，因此方案无需迁移旧格式。本次仅分析和离线实验，未改生产格式、未重启、未删库或启动创世同步。

本次精确切面沿用已通过完整 MuHash 复算的 **5,715,086** 高度副本，以便与上一轮逐项对比。实验结束时线上已到 **10,015,434**，这不是本报告的数据切面，不能将早期游戏合约占比外推到 10M 或后来的成熟高度。

## 数据依据与测量边界

- 扫描 `2026-10-19T01:23:01.00337449Z` 至 `2026-10-19T01:25:43.615898238Z`，复用一致副本，无新增停机。
- 物理源行数 `[1349700, 89, 45366888]`，三个源族的长度分帧 SHA-256 **全部等于上一轮 MuHash 验证通过的源**；完整 HEAD 的块号、块哈希、TxNum、root 同切面。此次未重复数百万次 MuHash 算术，依赖相同全源字节证明。
- 599 个副本文件预检查通过；独立本地再次检查分类、域、大小桶、账户、频率与区间的行数和字节总和。
- 后台受限为 1 核、2 GiB、低 I/O 优先级。运行服务始终为 PID 23101、原 bc939af2 二进制；结束采样 active=true、paused=false。
- SST 对照使用**全部对应行**，4 KiB 数据块/索引、restart=16、Bloom=10 bit/key、Pebble v4、每 500,000 行分文件；同时测试 Snappy 和不压缩。352 个对照 SST 的块校验和全部验证通过。
- 对照大小是相同数据在隔离 SST 中的真实文件字节，**不是生产混合 LSM 的可精确归属字节，也未包括 history/冷库、WAL、旧版本和 compaction 暂存**。当前实现默认 L0–L5 不做块压缩，底层使用 Snappy，因此同时给出两组数据；不能直接将两组结果相加为线上节省。

## Storage value：大量 uint256 只是小数值

全部 payload 都是 32 B，**没有全零值**。原值中的前导零合计 **686,848,444 B**；用最短大端字节保留数值后，payload 仅 **175,256,452 B**，均值 **6.505248 B/行**。这是精确字节分布，不能解释为等比例物理节省，因为 Snappy 已经压缩了许多零。

| 9–20 B | 4,993,116 | 18.533674% |
| 21–32 B | 752,601 | 2.793538% |

**76.245931%** 的数值可装 uint32。其中值恰为 1 的有 371,957 行，其余一字节值 9,198,164 行。保留数值含义及 presence 即可；若采用去 wrapper 的物理表示，必须由读取 API 独立返回存在位，不能混淆空值与不存在。

## SystemShielded：几乎全部是同一个空树根的逐块副本

共 **5,715,088 行、537,218,249 B 逻辑数据**，全部为 current generation。

| 子键 | 行数 | key B | 包装 value B | payload B |
|---|---:|---:|---:|---:|
| `mti- + height`，块高到根 | 5,715,086 | 348,620,246 | 188,597,838 | 182,882,752 |
| LAST_TREE | 1 | 62 | 9 | 8 |
| root 到 tree | 1 | 85 | 9 | 8 |
| 合计 | 5,715,088 | 348,620,393 | 188,597,856 | 182,882,768 |

逐块索引高度恰为 **1…5,715,086**，无缺口，根只出现 **1 种**：

`fbc2f4300c01f0b7820d00e3347c8da4ee614674376cbc45359daa54f9b5493e`

它与仓库 Sapling 空树深度 32 的交叉验证向量一致。全部逐块索引可精确表示为一个闭区间 **[1, 5,715,086] → 该根**。本切面未发现 CURRENT_TREE、note/nullifier/proof-cache 或未知子键；两条树记录仍须保留。

来源是 `MerkleContainer.SaveCurrentAsBest`：发现上块根可复用时仍调用 `WriteMerkleTreeRootByBlock(blockNum, root)`；block finalizer 每块都会调用它。因此这是**每块新增一个索引 key**，不是隐私交易量随高度增长到数百万笔。该记录还进入 MuHash 和正常历史生命周期。

适合的运行时表示是**根变化点 + 已提交执行高度的上界**，相同根不新增行；按查询高度找最近变化点。实验使用显式起止区间以独立保留覆盖范围，但运行时不能每块改写 end，否则仍有写入和历史；应使用已有 canonical cut 作为上界。查询创世前、未索引高度或未来高度仍应返回不存在。完整设计见 [新格式设计](../superpowers/specs/2026-10-19-storage-shielded-compact-format.md)。

## 全量 SST 对照：数值编码比单独缩键更有效

Storage 紧凑键模型为 `owner20 + generation8 + slot-tail16`（44 B）；每个账户/代另存一条 16 B slot 前缀元数据。表中**已加上全部必要前缀元数据 SST**。最短数值模型去掉 presence wrapper 及前导零，不丢失任何数值；零但存在的行应保留 SST presence 语义。

| 方案 | 块压缩 | 基线 SST B | 方案 SST B（含所需元数据） | 减少 B | 减少比例 |
|---|---|---:|---:|---:|---:|
| Storage 仅紧凑键 | snappy | 666,190,038 | 641,588,426 | 24,601,612 | 3.692882% |
| Storage 紧凑键 + 最短数值 | snappy | 666,190,038 | 500,920,258 | 165,269,780 | 24.808203% |
| Shielded 连续区间 | snappy | 47,133,615 | 919 | 47,132,696 | 99.998050% |
| Storage 仅紧凑键 | none | 1,603,412,077 | 1,513,018,750 | 90,393,327 | 5.637561% |
| Storage 紧凑键 + 最短数值 | none | 1,603,412,077 | 785,552,235 | 817,859,842 | 51.007464% |
| Shielded 连续区间 | none | 299,557,852 | 974 | 299,556,878 | 99.999675% |

仅缩键逻辑上每行少 37 B，共少 **996,808,786 B**，但 Snappy SST 仅少 **24,601,612 B（3.69%）**，说明不能拿重复 key 前缀的逻辑大小直接推算物理收益。

数值编码加缩键在 Snappy 条件少 **165,269,780 B（24.81%）**，在不压缩条件少 **817,859,842 B（51.01%）**；这是更大的 Storage 优化项。Shielded 索引在 Snappy 条件少 **47,132,696 B**，不压缩条件少 **299,556,878 B**。索引外的两条树记录在两侧保持相同，未计入该对照。

该切面中 Storage 数值编码的绝对 SST 字节收益大于 Shielded；Shielded 的优势还在于消除数百万个索引行以及每块相关写入/累加器工作，但**尚未测出端到端同步速度提升**。history/冷库的额外收益应在实现后的完整重放中单独测量，不能与这里的 latest SST 直接相加。

## 推荐实施顺序与边界

1. **Storage 紧凑数值作为主要空间优化项**。统一 current read/write、缓存、history before-image、快照和 MuHash codec；保持逐槽历史，避免把几个槽位打成大值后重新引入整页历史放大。键前缀可顺带缩短，但不是独立大头。
2. **Shielded 变化点索引作为主要行数/写入优化项**。保留按任意已执行块高查询根的语义，保留 root-tree 等验证源；补齐 overlay predecessor、as-of、reorg、缺口/未来边界与恢复后继续执行测试。
3. **字典与更激进的页编码后续评估**。当前已存在较强压缩和多处缓存，先取得前两项的实际全链收益，避免新索引、读放大或历史整页重写抵消收益。

用户允许新本地格式从创世同步，所以不做旧数据库迁移约束；仍需显式版本化 physical source/element codec/快照，确保新库的全源 MuHash、历史与恢复彼此一致。任何生产清库或上线属于后续具体实施，本轮没有执行。
