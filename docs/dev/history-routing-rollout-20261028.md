# 冷历史路由上线与磁盘分布（2026-10-28）

## 发布与过渡问题

`7669b2de` 已通过既有全仓 Sapling 部署测试并上线，运行二进制为 `c19a115219b35be299d1c66309b92758643b4c8eecf14a9f4d31e6e7c641cb84`，从现有高度继续同步。上线后的三个创世/341/342 余额返回正确，342 交易定位正确，但首个 9M eth_call 在客户端 180 秒上限超时，不能将此次上线称为性能验收通过。

现场轻量路由只有 1,088 / 33,093 个冷源，metadata 页为零。之前固定副本的 2 秒结论使用全覆盖辅助路由。新读路径在轻量路由覆盖不足时跳过了旧大路由已有约 25,600 源的负证明，变成大量权威随机读取；这是应修正的启动补建过渡行为。不能将超时掩饰成返回值正确，也不向生产并发复制固定副本 manifest。

跟进补丁只改 `history_segment.go` 的读路径：小路由覆盖当前 exact pair 时仍独立查询；未覆盖时惰性使用完整物理认证、只保留本批键的旧 broad 路由。首次 broad 加载收齐整个批次的系统键，防止 metadata 先加载时漏选小系统键。没有覆盖证明则继续权威读取，不改变状态、历史值编码、MuHash 元素或持久化格式。

本地相关 Small/SystemSelected/Metadata 用例、定向 race、vet，以及正成员的部分 broad 覆盖回归均通过；Astra 对实际 diff 只读复核通过。原生服务器使用相同 H=45,836,827、Tx=4,240,407,293 完整固定副本，两种索引覆盖分别复测，6 个 HTTP 返回全部为 207：

| 条件 | 新进程首查（OS 缓存未控制） | 同进程热查 |
|---|---:|---:|
| 过渡补丁、没有新路由 | 75.2304 s | 8.9631 s |
| 过渡补丁、新路由完整 | 3.5758 s | 1.8998 s |

每格仅一个样本，用于确认功能和是否存在明显退化，不计算 p95，不把不同覆盖的差值或生产 180 秒超时当作严格同负载 A/B。首次请求仍受文件页缓存影响。下一步发布该过渡补丁，复用本轮刚完成的全仓测试，仅追加相关原生测试/固定副本验证；不重复全状态扫描。新路由继续后台补建，尚不承诺线上立即达到全覆盖副本的 2 秒。
