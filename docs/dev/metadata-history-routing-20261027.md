# 9M 冷读后续：元数据路由及历史捕获修复

本轮仅修改本地候选和隔离测试目录。生产继续运行 `d11f4a57fa32`，没有推送、部署、启停、改参数或修改生产数据库。此前完整 HTTP 采样和身份记录见 `ninem-cold-prefetch-20261027.md`。本报告的性能数字仅属于固定 141 键冷库预取支路，不能作为完整 HTTP eth_call 的延迟。

## 剩余瓶颈与修复

此前虽然独立系统键路由已覆盖 29,658 个冻结源，但合约 `ContractMetadata/meta` 查询仍要读取旧 66,948,766 B 大路由，继而回退 4,058 个未覆盖源。此前跟踪在这个单键查询中看到 4,058 对 accessor/history 打开，约 1.057 GB 实际读取，耗时约 41 秒；这是带跟踪样本，不能与无跟踪时长直接比较。

新增独立 `metadata-history-routing` manifest 引用。格式上每页最多 256 个精确 history/accessor pair ID；默认后台每次处理 64 个源，空元数据源只占 40 B；非空源增加固定 1,024 B Bloom。哈希使用完整物理键，包含 owner、generation、domain 和任意逻辑键。Bloom 只用于排除不可能的源，正结果仍读取 canonical 数据。未覆盖或被替换的源走原有回退；损坏的已引用页报错，不把错误解释为不存在。

每页完整校验物理 SHA256，查询仅保留当前页。页构建按完整认证的字典生成证明；严格导入另行完整遍历字典。后台每次扫描有界，unsupported/oversized 源保持未知并通过游标让后续源获得机会，不能因单个不支持的源永久阻塞维护。页按范围退休，读租约和已发布 manifest 保护仍有效。已覆盖元数据查询不再载入旧大路由；其他路由及未知源回退保留。

冻结输入共 29,658 个源，生成 116 页、1,190,032 B。构建时从旧路由等价迁移其已覆盖且已完整认证的 25,600 个空源证明，另外完整扫描 4,058 个尾源；随后严格核验对全部 29,658 个源独立完整扫描，不借用迁移证明。canonical 引用、行、Seq、交易范围和前沿不变。

## 必须单独修复的历史正确性缺口

真实历史阶段测试证明，旧 `SetContract` 只有 typed metadata journal，而 canonical history collector 没有处理它；元数据物理 KV 又延迟到 Commit 才写入，在 `captureAtCommit=false` 的实际区块路径中，交易和 block-final history 都已完成。结果是 metadata 修改没有对应旧值历史。例如高度 1 的元数据改为高度 2 的值后，旧历史读者可能返回高度 2 的值。

本轮将元数据原生编码的不可变字节在 `SetContract` 时放入有类型包装的 KV journal，collector 捕获 canonical 前镜像，投机写集仍对应 typed metadata cell，避免和 generic alias 重复发布。缓存克隆输入，覆盖调用方原地修改指针的场景。ABI 删除继续在 block-final 执行，保留同一区块删除后重建的原语义；只将最终清理提前到 block-final history flush 之前。

补齐推测执行读桥接：缓存不能保留更旧边界的元数据；typed protobuf 与 generic 原生 KV 按 writer 选择最新值，两种别名都记录读依赖，缺失也记录。相同 writer 的双别名保守拒绝；被较新 generic 覆盖的旧坏 typed 不解码。Apply 写集在校验前后及每次写入后检查 sticky state error，不能将失败的 before-image 读取当作成功发布。

新增辅助路由不能补回已经遗漏的 canonical 历史。若需要旧区间元数据历史完整，必须重放相应历史执行或从创世重建；本轮没有执行生产重建。最新状态 MuHash 一致也不能独自证明历史旧值没有遗漏。冻结目录元数据为空这一事实还意味着本轮实物性能样本不能代表修复后未来非空元数据的所有密度；非空、任意键、最大 generation 和饱和 Bloom 另有正向及保守性测试。

## 验证范围

本地 `core` 完整包（900 秒 timeout，最终约 316.9 秒）、`core/state`、`core/rawdb`、JSON-RPC、actuator 测试通过；snapshots 完整包、相关 race、vet 和 gtron 构建通过。原 300 秒 core timeout 是总包时间限制，改为 900 秒后完整通过，未删测或跳过失败。

新增回归覆盖多交易 before-image、原地修改、无效 no-op、输入后续修改、rollback、删除后 generation 重建、typed 与 serial 发布、延迟 ABI、独立 MuHash 重算、签名快照及恢复后完整根；路由测试覆盖正负成员、取消、损坏、语义伪造、部分覆盖、source 替换、维护公平性及退休保护。

服务器原生路由、最终 state 和 core 相关测试均通过；固定输入全量字典独立核验已完成，116 页、29,658 个源，用时约 2,091.6 秒。实际构建约 472.9 秒。另测默认 64 源布局：464 页、1,201,168 B 逻辑大小、1,900,544 B 文件分配大小；全部源 ID、成员计数及过滤器字节与上述严格核验结果逐项相同。256 源布局文件分配大小为 1,425,408 B。

在 3,144,020、5,000,000、9,000,000 三个历史窗口分别恢复 20 个区块，共 22,496 行、60 个交易范围。原始、候选、恢复结果的完整行 SHA256 相同，比较包含 Seq；不是只比较值。最终参与原生 state 检查的 20 个产品文件与本地验收源码 SHA256 相同。

此前 11.8M 完整一致状态副本已删除，用户确认没有其他副本。当前仅有冻结的不可变冷目录，因此本轮无法完成同一完整状态下的新旧 HTTP eth_call 对照，也没有全量重算当前最新状态 MuHash。不会用活动 Pebble 文件复制冒充一致副本，不借用此前不同源码的核验回执。


## 固定冷目录的实际性能

从线上 9M 请求提取同一批 141 个键，查询交易范围 `[415035058, 3640325098)`，固定冻结的 29,658 对 history/accessor。三组结果逐行相同：39 个命中、102 个不存在。基线 B 为冻结输入上的原路径；中间候选 C 已有独立小系统路由；最终候选 N 再增加元数据路由及本轮优化。它们都不是已部署的新版本。

OS-cold 试验同机、同 unit 限额（2 CPU、4 GiB）、同输入、相邻交错顺序 B/N/N/B。每次启动新进程，仅对实验专用 inode 执行 fadvise；每个实际打开文件都有 mincore 冷驻留证明（计时前驻留页比例低于 1%）。没有执行全局 drop_caches。普通读取和复制仍消耗主机 I/O、可能间接影响共享页缓存，不能据此声称生产完全没有间接负载。

| OS-cold 布局 | B 两次耗时（秒） | N 两次耗时（秒） | 中位数 B → N（秒） |
| --- | --- | --- | --- |
| 默认 64 源/页 | 42.8984、43.5802 | 0.71484、0.65020 | 43.2393 → 0.68252 |
| 256 源/页 | 62.0658、41.3315 | 0.49819、0.49531 | 51.6987 → 0.49675 |

每组只有两次有效冷样本，不报告 p95，不将波动较大的基线中位数推广成所有请求的加速倍数。默认 64 源布局实际打开 453 个文件；256 源候选 146 个；基线 8,157 个，均逐项确认在私有 inode 及冷驻留证明范围内。默认布局页数较多，冷读略慢，仍消除了数千冷段的回退。

独立的交错热缓存试验只纳入进程内后续调用且 `read_bytes == 0` 的样本：B 中位数 5.1397 秒（n=4）、C 1.4023 秒（n=8）、N 的 256 源布局 0.25662 秒（n=8）。默认 64 源布局另有两个热样本，中位数 0.27118 秒。不能把进程首次调用自动称为 OS-cold，也没有把存在实际读取的样本混入零物理读热组。

这些数据证明元数据缺失判定回退是主要瓶颈，并非 TVM 执行本身；其消除同时大幅减少解码分配和小读取。页数随源数量增长仍有扫描成本，且修复历史捕获后未来非空元数据会增加 Bloom 正结果。当前非空分布、全链持续冷发布吞吐及索引维护增量成本尚未完成实测，不能承诺没有同步回退。后续可在 canonical accessor 写出时同步产出过滤信息，省去独立完整扫描；这不属于本轮已验证改动。

## 样本审计与证据

第一次 OS-cold 采样的成功打开解析器漏掉四个未完成的 open 尝试，独立审计发现基线实际读取集合并未全部私有化。该组四个计时样本已全部作废，原始文件与原因保留在 `rejected-initial-samples.json`，未用于上表。补齐四个文件的 SHA256、独立 inode 及冷驻留证明后，重新交错采样，并按全部实际 open 尝试重审 B/N 覆盖。256 源表仅采用 `revalidated-os-cold-*`；默认 64 源复测也使用修正后的证明。

完整主证据包为 `AAA-gtron-metadata-routing-acceptance-20261027.zip`：49,450,207 B、777 个成员，SHA256 `093ac35b542220f5c6e6a46c4e6961099e2a43e628fefad3dd299d33a5baf4f7`。本地逐项校验全部成员及完整 manifest、canonical 源身份、两种分页全部字节、全部查询、恢复行和实际打开文件范围。早期较小的 final ZIP 缺少三个 gzip 完整 manifest，已通过这个总包补齐，不能单独拿早期包作为完整验收证据。
