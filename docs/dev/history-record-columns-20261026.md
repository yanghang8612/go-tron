# 128 KiB 记录头分列压缩：第一阶段筛选

**找到值得继续验证的路线，但尚未达到整库验收或上线条件。** 保持原 128 KiB 独立解码粒度，按页压缩 V6 的记录头，
14 个真实文件的完整编码长度计算值从 **155,751,572 → 138,569,084 B**，少 **17,182,488 B（11.03198%）**。
八个相同小页的完整解码中位数为 **0.211564 → 0.227576 ms（+7.56875%，多 16.013 µs/页）**。
这些是页级筛选结果，不能替代完整 HTTP `eth_call`，也不能外推成全库已回收空间。

代码只有未接入默认读写路径的私有编码/解码函数及测试。没有推送、部署、删除数据库、操作生产 gtron 或修改预算。
本轮观测生产仍为此前已停的 `inactive / PID 0`；所有输入及非获胜实验均保留。

## 做了什么

V6 每条记录的固定头为 21 B：frame 长度、key ID、TxNum、旧值存在位、旧值长度。
frame 长度由旧值长度精确重建；TxNum 用页内单调差值；存在位打包；旧值长度独立 varint。
key ID 对照三种方案：绝对 varint（mode 0）、有符号差值（mode 1）、四个字节平面（mode 2）。
按页比较普通 Zstd 和三种分列编码，取完整压缩帧最小者；不划算的页/整文件保留普通编码。

页内只记录首个完整头的位置和数量，后续位置按原始 frame 长度前进。所有旧值保持不解释、不删字段的原始字节；
前缀、跨页头及部分旧值均为 literal。没有账户还原链、跨页字典或外部基值；逻辑 offset、key ID、交易号和记录顺序均能逐字节重建。
HRC2 页头 36 B，明确记录各列边界及原始页 CRC32C；解码前限制页长、数量与列长，拒绝非规范 varint、越界、溢出、坏 flag 和截断。
完整文件认证及规范流 SHA256 的验收要求保留。HRC2 目前不是可由主网 writer 发出的物理容器。

## 同页空间对照

服务器 lab：`/data/gtron/history-record-columns-20261026-01`。固定输入沿用上一轮的 14 文件：
九个来自 head 11,818,192 的 V11 固定副本，五个来自 25M–35M 资料；不是当前主网全库，也不是成熟区间全量统计。
合计 **10,291,276 条记录 / 596,391,700 B 规范流 / 4,565 个页**。
1,591 个跨页头保持 literal，其余完整头都参与候选编码。

普通 Zstd 使用原页边界、相同 encoder；逐文件重压缩的完整长度恰与源文件相等。
下表计入实际压缩帧长度、页内头、模式字节、完整投影页表与 footer；每种变体都计入整文件 fallback。
**尚未生成、fsync 新物理容器或统计分配块，因此这是编码长度计算值，不是实际磁盘回收量。**

| 范围 / 方案 | 源文件 B | 完整投影 B | 节省 |
|---|---:|---:|---:|
| 全 14 文件 / mode 0 | 155,751,572 | 139,263,368 | 10.58622% |
| 全 14 文件 / mode 1 | 155,751,572 | 141,098,992 | 9.40766% |
| 全 14 文件 / mode 2 | 155,751,572 | 139,792,241 | 10.24666% |

成熟样本的字节平面更有利，固定样本的绝对 varint 更有利；不应按这几个文件硬编码高度门槛。

本轮收益以 V11 为基线，不能叠加上轮 1 MiB 大页账户差分的 7.89 GB，也不能把 12.54% 直接乘线上成熟区间大小。

## 解码成本与非获胜对照

八个相同逻辑位置的 128 KiB 页，三个来自固定样本、五个来自成熟样本。
普通压缩与候选的完整 Zstd 解码、重建和 `bytes.Equal` 均在计时中；压缩帧驻留、输出 buffer 重用。
每版十个正反顺序批次，每批 256 次解码。候选在八页中选择四个 mode 0 和四个 mode 2；
最后单独重扫全部 14 文件，补齐相同逐页选型策略的完整空间计算值。

| 对照轮次 | 普通 ms/页 | 分列 ms/页 | 结论 |
|---|---:|---:|---|
| HRC1：逐页 SHA256 | 0.210937 | 0.593223 | 额外 CPU 很大 |
| HRC1：还原循环优化 | 0.210990 | 0.593704 | 没有可靠改善 |
| HRC2：CRC32C 页检查 | **0.211564** | **0.227576** | 额外约 7.57% |

21.32 秒的诊断 profile 中，SHA256 AVX2 flat **45.31%**，Zstd 主解码 flat **40.12%**；
`decodeHistoryRecordColumns` flat **3.96%**、累计 **53.47%**。累计包含 SHA256，不能与 flat 相加。
这解释了只改还原循环没有明显改善。HRC2 保留原有整文件 SHA256 认证及完整规范流 SHA256 验收，
仅把实验额外添加的页检查改为 CRC32C；所有页的逆变换和八页完整 Zstd oracle 均保持一致。
这不是取消完整文件认证，CRC32C 也不被当作密码学认证使用。

以上不含磁盘 I/O、分配、正式 HTTP、热 history 尾部或同步背景负载。不能用 7.57% 宣称 HTTP 只慢 7.57%，
也不能根据 16 µs/页推断线上长尾已经解决。候选容器接入后必须重新测完整请求。
