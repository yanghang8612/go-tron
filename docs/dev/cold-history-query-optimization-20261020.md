## 已实施

- 修复 first-change 在 posting 索引区间无命中时直接返回、遗漏未索引热尾部的问题。
- 先找冷库最早变化，用其**包含端点**的区块和 TxNum 上界约束热查，仍比较同一交易内的 Seq；
  重叠数据和更早的热变化不会被跳过。回归控制查询读取 63 个无关热 pack，候选读取 0 个，返回相同目标值。
- StorageAt 已恢复目标账户 envelope，直接使用其中的 generation 查询元数据，省去再次恢复 generation 的全历史扫描。
  覆盖 metadata 修改、SELFDESTRUCT、不同 TrxHash/Version 的重建合约，以及完整冷热历史路径。
- 创世 cut=0 时保留显式热 StateTxRange(0) 的优先级；缺失时直接使用规范创世边界，免除全部冷段的负查。
- 把 RPC context 传入热 first-change、冷批量点查和 block→TxRange 查找的底层读取；保留有上下文的 header、字典与范围恢复，
  不因 ReaderAt 包装丢掉既有类型携带的 header/tx-range 缓存。额外覆盖 maintenance 上下文的批量读取，避免 eager preparation 与显式绑定重复安装 accessor。取消仍受一个解码块/系统调用的粒度限制。
- 对 `.seg` 头部跨次打开的解码采用有界强摘要缓存：最多 8,192 项、每项最多 128 B 的解码前缀。
  **每次新打开仍读取当前完整压缩块并计算 BLAKE2b-256**，与解码长度一起标识缓存；同次 reader 内的复用遵守原 decoded-block 缓存生命周期。
  不保留 fd、manifest、context 或“某键不存在”的跨请求断言。尺寸、range、dictionary、CRC 等原检查继续执行。
  BLAKE2b 仅标识内存缓存；磁盘 SHA256、MuHash 元素/根和共识计算均不变。额外还有有界索引元数据，不能把 1 MiB 前缀载荷误称为总 RSS。

没有实施基于 stat 的负查询缓存、跳过认证的 accessor-first 捷径或新的全局键索引。
大范围小读缓存和 reader 内页缓冲在此语料上收益不足，已从最终候选移除。

## 余下大头与证据

内部缓存候选在 maintenance 防重复绑定补充修正前的独立 profile：12.73 秒墙钟、14.30 CPU 秒，包含整个 54×3 测试和 Go 测试/GC。
其中 header 当前字节校验的 BLAKE2b 为 **3.97 CPU 秒 / 27.76%**，系统调用平 CPU **3.68 秒 / 25.73%**；
Zstd DecodeAll 累计 **0.93 秒 / 6.50%**。这是实验进程 CPU 占比，累计项有包含关系，不能相加或等同于 RPC 墙钟占比。该 profile 的 Background 请求不进入后来修正的 maintenance eager-preparation 分支，最终效果以补充修正后的重复对照为准。
前一候选的缓存 SHA256 本身占约 50% CPU，解释了单纯解码缓存收益受限；更大缓存和页缓冲没有足够收益，未保留。

负查仍逐段访问，随段数增长，8,192 项缓存超出工作集容量时收益也会下降；下一步大头是**经认证的键缺失证明和多键共享目录/热尾部扫描**，
以减少必须读取和验证的段，而不是再扩大缓存或放宽取消期限。
accessor-first 必须先具有与 manifest、真实 history bytes 和 dictionary 绑定的证明，不能仅凭 stat 或范围相等跳过校验。
这轮先收敛在现有格式的读路径，保留首填充和小正查询的实测限制；当前高度整 RPC 效果仍需以后获准发布后另测。
