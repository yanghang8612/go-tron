# 未覆盖存储冷段的分页排除索引

本轮在相同 H45,836,827 一致副本上继续定位首次历史 `eth_call`。
没有 master 推送、生产部署、服务启停、生产缓存清理或 canonical 数据修改。
线上仍是 `52aea62ef56799b7e6c1365293123dd029286935`。

## 确认的瓶颈

合约 `0xa4997124a328a4615eab437cede31da47a31b375`，calldata
`0x9fa6a6e3`。固定副本有 32,036 个有效 history/accessor pair，旧 broad
路由覆盖 25,600 个，另外 6,436 个为未知。metadata 已在此副本补齐，账户缺口
为 31；这与线上更大的账户/metadata 缺口不同。

只在独立源码归档注入批次计数，不把诊断计时当作正式 A/B 性能：

| 高度/批次 | 进入 canonical 读取的源 | rchar | read syscall | 是否命中变化 |
| --- | ---: | ---: | ---: | --- |
| 20M 第一次，storage | 6,436 | 624,412,217 B | 93,269 | 否 |
| 20M 重复，storage | 6,436 | 624,412,219 B | 93,269 | 否 |
| 9M，storage | 8 | 6,837,207 B | 112 | 是 |
| 15M，storage | 8 | 6,826,418 B | 101 | 是 |

20M 诊断批次首次 13.098 秒、重复 1.094 秒，说明文件缓存能掩盖相同的读取
放大。它需要确认没有后续变化，因而不能像较早高度那样遇到第一个变化即停止。
TVM 指令执行不是这部分耗时的大头。

对 6,436 个未知源均匀分层抽样 128 个，完整认证并枚举其字典：目标
owner/generation 前缀及目标 slot 均为 0/128。每源前缀数最大 1,043，按实际
数量分配的 Bloom 位图总计 204,800 B。抽样只能证明这些源，不外推全部源的
真实成员分布。固定 1 KiB 位图不足以覆盖较密源，采用自适应容量。

## 实现与安全边界

新增独立 `storage-history-routing` 辅助 kind，`GTSTOR01`。每源按
owner/generation/domain 的 31 字节前缀建立过滤器，8 次 double-hash probe，
每前缀至少 16 bits，容量为 2 的幂；非空至少 64 B，单源最多 65,536 个前缀。
先认证并完整收集有界 hash 集合，再分配位图，预算超限不生成部分否定证明。

每页至多 256 个源且至多 1 MiB，源身份包含精确 history/accessor pair。
SHA256、页头、排序、行数、位图尺寸、源范围均认证。请求仅在即将读取 canonical
源时惰性加载当前页；不提前扫描全部索引。缺失、损坏或源身份变化时回退原路径。
完整零成员证明与未知源分开处理。新增页不改原状态值或历史旧值。

修复了提前命中的队列问题：较早正候选已经排入 read-ahead 队列，后续源全部
被过滤时，必须先消费最早待完成任务，才能停止后续索引读取。300 源/两页的
回归在去掉此修复的 overlay 中失败（读两页），保留修复时只读一页。

重叠页修复带回游标前仍有效的证明；超过容量就推迟，不能发布缩水页。
逐页发布沿用进程内 manifest 锁、重读受影响 refs 比较和现有读租约。
副本补建实验单写者认证父 manifest 后一次性 Integrate；这不等同于运行时
已接入补建调度。当前产品原型仍需有界后台调度，不能仅靠发布二进制宣称线上
覆盖已补齐。

## 验证范围

本地 snapshots 全包 231.968 秒，filter/metadata repair race 79.803 秒，
新增发布冲突/退休租约 race 3.643 秒，以及相关 state/rawdb/core/gtron vet 通过。
原生 Sapling focused tests 24.701 秒通过。

canonical refs、固定 HEAD/Tx/MuHash root 收据及完整 HTTP 返回值会随原始证据
独立复核。本轮不重复全状态 MuHash 或整库恢复；已有一致副本的根仍是
`4bb19b7a938ba6c865820ea86f5239235172f84923c350b04c4b0eb75743b627`。
这不构成一次新的全状态重算或生产快照恢复验收。

正式矩阵为 before/control/indexed/indexed/control/before，各进程依次访问
9M、10M、11M、15M、20M，每高度两次，共 60 次。before 使用已验证的旧52
HTTP host；control 使用新代码和原副本；indexed 使用相同新代码及新增辅助页。
CPU quota 200%、GOMAXPROCS 2；OS 缓存共享且未受控，不把每高度第一次视作
独立冷缓存。功能分支 fetch 曾触发 Git 自动整理，后台同步也继续运行，因此
wall time 不适合推出固定加速倍数。

另有独立文件访问观测，只统计访问过的不同路径，不冒充 open 次数；以及仅对
新增索引建立独立 inode、确认派发前零驻留页的测试。后者保留 canonical 和
旧路由缓存，不能称为整节点冷查。

## 原生结果及独立复核

原生矩阵源码 `7a1d189ad2cd3927a1d9a506c418f2a34e22ab23`。后续
`19bdd0dd` 只为重叠修复加入更早容量退出及离线观测工具，没有改变此次无重叠
补建/读取路径。共 421 个预算切片，704.247979 秒，产出 421 页、10,119,232 B，
精确覆盖 6,436 个当前 pair；最大页 73,176 B，完整构建实际最大前缀数 5,436。
页数较多是 128 MiB/2 秒软预算切片的结果，并非每页都填满 256 源。

完整 loopback HTTP，各轮每高度第一次的范围：

| 9M | 0.702–2.543 s | 0.813–1.543 s | 0.744–1.188 s | 0.610–0.610 s |
| 10M | 0.607–0.679 s | 0.592–0.606 s | 0.617–0.645 s | 0.658–0.936 s |
| 11M | 0.623–0.746 s | 0.585–0.633 s | 0.606–0.738 s | 0.552–0.597 s |

20M 的稳定工作量差异独立于上述 wall-time 缓存波动：

| 完整请求指标 | control，无新索引 | indexed，有新索引 |
| --- | ---: | ---: |
| rchar | 640,297,588–640,297,591 B | 92,953,489–92,953,493 B |

完整请求逻辑读取约降 85.5%，read syscall 约降 97.9%。421 页逐页认证、重建
精确 pair 身份后，6,436 个过滤器对该目标前缀全部给出否定；这不是再次枚举
全部 canonical 字典。文件观测的四次 control、四次 indexed 均无 overflow：
不同 `.kv` 和 `.seg` 各从 6,475 降至 72，`.route` 从 358 增至 779。
这些是整个请求跨批次的路径并集，不能用两组路径数之差直接当作 storage
批次的源数。

## 后续

剩余线上问题仍包括账户未知源、metadata 覆盖债务和未索引热尾。本轮分页
过滤器针对 storage 的否定扫描，不能解决全部慢查询；也没有证明任意历史
合约在生产负载下都稳定 1–2 秒。账户旧构建器会重写约 3.4 GB 全局表，不能
通过简单提高调度频率解决，需独立的有界增量设计。
