## 实际空间账本与差分归因

全部 4,609 段都转换并验证；所有表、mode 字节、footer 和校验开销均计入，未只算差分 payload。

同页普通压缩解释了总节省的 **99.99517%**。

203,175 个页中仅 **176 个（0.08662%）**选择账户转换，175 个含数值差分。
这些选中页的 ADP1 值共 1,279,822 个：完整 checkpoint 274,238，差分 1,005,584，其中数值 913,877、prefix/suffix 91,699、mask 8，实际最大深度 4。

## 实现与边界

新增实验物理容器版本 4（`gtcend04`）。规范 V6 流、所有逻辑 offset、key ID、交易号、记录序号和旧值字节不变。
随机查询仍须解码整个独立页；四层约束限制的是基值依赖，不是只读四条记录。
每页最多 1 MiB，账户旧值最多 4 KiB；跨页、缺失、空值及更大值保留完整原字节。
ADP3 按 owner key ID 在页内稳定排列账户值，单独保存 gap/length/permutation，恢复原始记录顺序；非账户字节作为 opaque literal 保留。
同 owner 的前一值作为候选基值，最多连续 4 层后写完整 checkpoint，解码器硬上限 8 层，禁止跨页或跨文件引用。
差分比较 prefix/suffix、中间字节 mask，以及 V5/GTRC1/2 数值差分：后者要求存在位图、版本、所有 opaque 字段和尾部完全一致，
对 ZigZag varint 做显式模 2^64 的有符号差分，再重建规范 varint/RLP 长度；未知形状退回完整字节。
ADP1 内层与 ADP3 外层均核对规范 SHA256，拒绝越界、前向引用、未注册基值、超深、非规范 varint、坏 mask 和截断。

每页实际比较普通 Zstd、owner 分列、owner 有界差分的最终压缩长度，选择最小者；格式标记、页表和 footer 都计入文件大小。
离线 API 只有在整个新文件更小时才返回新 trio；伴随 `.idx/.kv` 字节完全不变，以新 stem 复制、认证和绑定。
API 不发布 manifest、不删除源、不推进任何 frontier；本轮独立 lab 驱动才重绑路由，并逐项核对 membership 和严格重建证明。
增加大页时保持原 reader 解码缓存字节预算：16 × 128 KiB 变成最多 2 × 1 MiB，至少允许一个完整独立页。

默认 `auto`、默认页大小及 CDC 策略未改。显式 `4` 是实验强制格式，没有同时选择大值 CDC；
从创世构建也不具有离线 API 的整文件保留原格式比较。`auto` 下的后续合并还可能选回其他容器，
因此离线变小不等于已验证长期冷发布吞吐或最优线上策略。本轮未推送、部署、操作生产服务或改写线上库。
写入每页最多尝试三次压缩，另有分列、差分和摘要成本；离线转换耗时同时包含完整认证和重读，不能直接当作生产冷发布吞吐。

## 同一固定副本的方法

基线接续上一轮 V11（本地提交 `b6a6fdf508b281f6864f888563e92eaa656be594`），不混入更早 V7/V8 的累计收益。
服务器 lab `/data/gtron/history-account-delta-20261025-01`；固定副本 head **11,818,192**、TxNum **601,386,177**，
冷历史 TxNum 前沿 **568,104,018**，hot prune block **11,488,345**。含 **4,609 个 `.seg` / 48,379,318,571 B**。
它不是当前约 40M 的整节点，亦不能替代上一轮 25M–35M 的全量旧值分布。
另有 14 个真实文件试探样本，其中 5 个来自成熟区间，只用于格式选择，不据此外推整节点空间。

原 `.seg/.idx/.kv` 全部保留；候选活跃目录以外的旧 trio 移到本 lab `original-source-pins`，inode/长度不变。
使用完整源 SHA、全规范流逐字节比较、严格 companion 验证与路由重建；最终再次重读所有 manifest 引用和普通压缩对照的 SHA/分配块。
文件长度、`st_blocks×512`、活跃目录 `du` 分别报告；保留旧数据与新候选期间，不能把活跃引用变小称为服务器已回收空间。
完整普通 1 MiB Zstd 对照沿用候选的页边界；原本普通页直接去掉 mode 字节并复用压缩帧，转换页还原后普通压缩。
包含全部 header/table/footer，fsync 并再次读取规范 SHA，单独归因“大页”和“账户差分”的收益。

完整 HTTP 使用原 host 驱动，SHA256 `10e6015af7666bf83b5c405543681c368b7537f428b8278a3344f0312aacd3bf`。
同一 Linux amd64 / Go 1.25.5 / Sapling、GOMAXPROCS=2、GOMEMLIMIT=3 GiB，正式 loopback RPC→历史状态→TVM→序列化路径。
合约 `0xa4997124a328a4615eab437cede31da47a31b375`，calldata `0x9fa6a6e3`；
3,144,020 / 3,144,021 / 5M / 9M / 11,817,936 / 11,818,191 / latest，旧值 oracle 6/7/63/207/225/225/225。
每高度每版暖 10 次、独立进程且 OS 不控制 3 次、私有文件 OS 冷启动 4 次；ABBA/交替顺序，trace/profile 排除出计时分布。
冷启动前对独立 inode 的完整 SHA 相同读集做 fadvise/mincore，低于 1% 才开始启动；不使用全局 drop_caches，也不驱逐生产 inode。
启动不计入延迟，OS 冷指启动前冷，启动期间仍可加载文件。
这些离线结果不含 SOCKS/Nginx/公网延迟或运行中同步节点的缓存竞争，样本量也不支持宣称消除了线上长尾。

MuHash 在相同固定 chaindata 上全量重算，校验候选 HTTP 二进制 SHA 和全部 803 个 SST/WAL/元数据文件前后指纹。
历史恢复用原副本、候选逐行摘要和实际 `RestoreStateDomainHistory` 写入隔离内存库后的回读摘要互相核对；
起点 3,144,020 / 5M / 9M，各 20 块。快照恢复、commitment 原子边界、compaction 和旧格式读取由相关全包测试补充。
没有对完整 11.8M 节点重新整库导出/导入。

## 后续取舍

本轮不进入默认格式，也不建议为这点差分收益重建主网库。保留实现为显式实验选项和可复现样本，当前默认读取粒度不变。
若继续做空间优化，优先保持最多 128 KiB 的独立随机读取单元，分离 TxNum、key ID、长度等重复记录头的列编码/varint，
或试验可独立定位的小块加有界共享字典。必须把字典、目录和认证一起计费，再用同页普通压缩与完整 HTTP 复测，不预报尚未测得的收益。
若试验按 owner 重排跨页账户版本，需同时重建逻辑定位映射，其元数据、恢复随机读和认证成本须独立量化，不能把逻辑重复字节直接当作磁盘收益。
查询方向仍优先针对既有热 owner 尾部 Snappy 解码和重复路由认证；本轮 trace 的 LSM/route/KV 读取未减少，扩大 `.seg` 压缩窗没有解决它们。
这次只完成授权的有界账户差分试验及验证，没有继续扩展实现上述新方案。
