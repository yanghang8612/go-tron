# 公共数据单次压缩：有界解码验证完成，暂不接入

后续原生验证和本机原始记录复算均已完成。有界缓冲减少了 HSP1 原型的
分配与解码耗时，但在相同缓冲复用条件下，仍比 V5 慢 **7.6895%**。
另一次排除逐页内存统计的 CPU 对照，CPU/完整一遍增加 **8.5303%**，
耗时增加 **8.4977%**。当前保留 V5 候选，HSP1 仍为未注册的隔离试验。
样本新增空间收益约 1.1%，不足以据此接受读取回退或宣布同步提速。

将交易号、长度、标志和旧值压缩一次，三种键列分别压缩比较。在原有
128 KiB 页内，三个固定样本的全部 1,817 页验证通过：1,806 个列页均更小，
11 个无法独立恢复注释的普通页保持原样。完整 37 项原始证据已下载并在本机
复算，未剔除任何页。本轮仅新增隔离试验；正式 Go 源码仍为
`3281b8fcd833df0066efba23ac68c6ed329f9a1534ea5be5c75002655b6e9150`
的 2,149 个输入。

这些编号是既有发布样本的 pair 索引，交易号范围也不是区块高度。样本来自
原来的 11.8M 固定副本；不能据此推算 25M–35M 全部数据的收益。

页总量从 50,016,427 B 降至 49,461,177 B，减少 **555,250 B**。每个原文件的
控制区均为 `28 × 页数 + 96` 字节；若继续采用同样长度的表、首尾元数据，
三份文件可从 50,067,591 B 估算降至 49,512,341 B，即 **1.1090%**。
原型的 49 字节描述头、两个压缩帧及所有模式字节均计入；尚未实际发布新物理
文件或重写整份库，线上回收量为 0。

每一页先验证旧 V5 编码能够逐字节重现，再核对原型恢复的完整 canonical
字节，包括跨页旧值及不完整头。已有列页的注释由已校验的 HRC2 和原记录
长度恢复。11 个普通页没有推断注释，两种试验路径都只运行普通压缩；其耗时
不能代表实际写入器比较全部候选的成本。

计时是交替次序的三次驻留内存、串行页级诊断。逐轮汇总再取中位数：编码
5.653488246 s → 3.443571677 s（**−39.0894%**），解码
0.563920625 s → 0.620970715 s（**+10.1167%**）。不包含文件读写、ETL、
索引、fsync 或 manifest 发布，不能换算成同步或冷发布提速。

原生 Go 1.25.5 的边界、race、构建和完整真实页测试均通过，耗时分别为
21.58、32.79、4.79、43.25 秒。私有单元实际限制为 2 核、4 GiB、Nice 15；
正式源码、24 个旧辅助源码、试验辅助源码及三份输入的前后校验一致。
构建后二进制 SHA256 为
`484acbb5c0cb2e1f887cb9c01889578c93df1402c57389ffc4a40fd4430f348b`。
原始失败记录也保留：首次环境缺少 `rg`；第二次 systemd 环境缺少 Go 缓存
路径，在编译前被 overlay 检查拒绝。成功试验采用显式 GOPATH、GOMODCACHE
及已有 Go 构建缓存。失败单元未重启，所有目录保留。

新表示仅是未注册的 HSP1 试验，正式策略和读写器没有接入。它没有新的完整
HTTP、MuHash 或快照恢复验收；此前 ordered V5 的成功结果见
[对应报告](history-columns-ordered-pages-20261026.md)，不能混用。
最初 HSP1 试验没有推送、部署、启停正式服务、删库或调整正式预算。那次
试验的正式服务身份前后均为 inactive/PID 0；后续试验的运行身份见下文。

后续解码器用一个最多 128 KiB + 36 B 的有界缓冲直接拼接 HRC2，两个
压缩帧各自仍受精确输出上限约束。canonical 返回值与临时缓冲分离；边界、
截断、损坏、错误恢复、八个独立调用方并发及 race 检查均通过。全部 1,817 页
逐页重现旧 V5 stored 控制和原先 HSP1 的 SHA，11 个普通页也保留。
原型编码器、正式源码和成功的旧证据没有修改。

六条路径均预热，在每页、每轮交错并反转次序；每个计时区间解码 8 次，
共 5 轮。先对整批页逐轮求和，再取中位数除以 8，得到完整一遍的诊断值。
所有输入驻留内存；“每次新建/复用”指输出与临时缓冲策略，不是磁盘冷/热缓存。

原生边界、race、构建、真实页检查分别用时 23.24、1,235.38、7.76、155.71 秒。
race 的用例执行本身为 7.528 秒，其余主要是清理后缺失缓存带来的 CGo 冷编译。
第一次尝试在 1,200 秒构建上限处超时，未进入测试；失败回执已保留。第二次
使用原缓存并延长构建期限，资源仍是 2 核、4 GiB、Nice 15，未调整正式预算。

另用相同的全部页做六个 CPU 窗口，顺序为 V5、HSP1、HSP1、V5、V5、HSP1。
每窗至少 20 秒，完整 canonical 核对与预热在采样外进行，窗口内没有
ReadMemStats、编码或文件读取。V5 每窗 44 遍，HSP1 每窗 41 遍；各组三窗
CPU/遍中位数为 0.461784159、0.501175951 秒，耗时为 0.460672217、
0.499818619 秒。全部六份原始 profile 已取回，本机 Go 1.25.5 重新生成的
flat/cumulative 表与服务器逐项一致，包含 flat 为零的函数行。

42 页的键模式选择发生变化，也应纳入列还原成本比较。

不直接固定为 byte-plane 键模式：根据已记录的全部候选成本，固定 mode 2
并保留普通压缩兜底会得到 50,588,227 B 页数据，比 V5 增加 571,800 B。
当前被选中的键帧总共 6,127,518 B；其余表示字节不变时，更轻键编码相对它增加超过
555,250 B（9.0616%），就会抵消本样本的全部新增空间收益。
下一步值得先做键列轻量编码的体积/CPU 联合小试，并按页保留 V5 兜底；
应先同时证明净空间与读取成本有利，再投入物理格式接入和完整发布验收。

这两次后续试验中，正式服务始终是同一个 active/PID 7788 进程，启动计数与
运行二进制 SHA 前后相同；2,149 个正式 Go/module 输入、24 个既有辅助输入
及三个物理输入的前后校验一致。正式 Go、默认策略、数据库、服务和内存预算
均未改动。本轮没有 HSP1 的新物理文件、完整 HTTP eth_call、MuHash 或
快照恢复验收；逐页 canonical 与 CRC 成功不能替代这些验收。
