# 同步期间按实际负荷限制历史冷化

用户要求继续修复积压，并特别指出 20M 以后冷化会显著干扰正常同步。保留全部历史查询、不清空当前库、不扩容或迁移 MySQL。本次沿现有内部格式修正运行时调度，延续已授权的 GitHub 提交、服务器 pull 和原生验证/部署流程。

9 月 8 日检查发现：普通冷化约 20 秒工作后等待 80 秒，五分钟冷化 34 块/秒而导入 96 块/秒；一次 880 秒冷段合并使完整维护达 902 秒，随后等待 3,610 秒。合并还在普通 builder 释放共享重任务锁之后运行，可能与 freezer 重任务重叠。详见 [现场检查](../../dev/genesis-sync-status-2026-09-08.md)。

## 设计边界

不按高度硬切换策略。相同块数/txnum 在后期可能包含更多状态变更、更大的旧值和更多事件日志；预算必须随实际工作量调整。CPU 空闲不是磁盘空闲，设备 busy 单一指标也不是已达到带宽上限的证明。固定容量下无法无条件同时保证导入零影响和冷化永远追得上；本次通过减少长任务、避免任务重叠与反馈控制降低干扰，不把短期窗口当全链验收。

1. **轻量负荷反馈。** Pebble 直接提供 write stall、L0 sublevels、memtable 数、实际停止写阈值和压实欠账；读取不遍历数据库。Linux 按 datadir 实际设备匹配 `/proc/diskstats`，用两个新鲜样本计算共享设备队列、读写 await 和 busy；缓存五秒，首点、回退、过期、失败或没有完成 IO 均保持未知。其他系统明确设备未知。
2. **硬准入。** 当前写阻塞、memtable 接近停止写阈值、L0 达停止阈值约四分之三时，共享 HeavyWorkGate 拒绝新的受管重任务且不安装冷却。history 额外五秒重试，已覆盖历史仍可验证/热裁剪。该保护是准入时刻检查，不能中断已经开始的任意文件系统 IO。
3. **密度反馈。** throughput 的在线 history 同时调整 block/txnum 上限。未取得批次观测时先取正常上限四分之一；之后由最近完整构建的耗时与输出字节估算下一批，遇密度跃升立即缩小，增长每批最多 25%。未知/压力、恢复、健康三个等级分别以 2/4/8 秒及 32/64/128 MiB 输出为软目标。完整区块是最小单位，因此首个密度突增批次或单个巨大合法块可能超目标，不截断或跳过历史。
4. **恢复迟滞。** 写阻塞、L0 压力、持续增长的压实欠账或持续繁忙且队列/延迟同时较高的共享设备降低预算；恢复需要多个至少间隔五秒的新鲜样本。未知设备不进入最高等级。history 类目标占空比为 20%、约 1/3、最多 60%；真实普通构建成本保留，包括单个巨大块。只将可选 merge 成本从 history 恢复中移出，不用固定成功等待上限掩盖昂贵普通构建。
5. **独立事件日志。** freezer 依赖的 event-log 补建遵守同一 history 准入截止与负荷反馈；初次不再直接做 65,536 块突发，按自己最近的时间/输出密度调整。其后置裁剪、可信段登记和 catalog 错误纳入同一外层完成握手。准入时已在同步的任务不能因完成时暂时变 idle 漏掉恢复。
6. **有界叶段合并。** busy throughput 仅合并原始叶，默认最多 512 MiB 物理输入（含 companions）、2 GiB 逻辑正文、800 万记录、16 个源段。接近预算再合并，不将每对小叶反复逐级重写；输出在 busy 阶段视为终端。单叶已超预算则保留独立文件，继续寻找后续可完成的连续范围。预读头部仅用于调度，正常 checksum、完整 companion 交叉校验、原子发布和 reader lease 规则不变。
7. **合并独立计费。** merge 自己持共享重任务锁，busy 合并拥有独立 3–60 秒恢复截止。history 的恢复期可以给已到预算的合并一次机会，但不得缩短既有 history 截止，也不能让每次刚完成 history 的三秒 gate 冷却永久饿死合并。避免给大合并加固定超时再反复从头校验/排序。

history 占空比不等于全部后台 IO 占空比：独立正文 freezer 仍有自己的完整分段工作，latest 全库构建也有现有的同步延期规则。共享硬门覆盖使用 HeavyWorkGate 的路径，不能宣称所有后台工作都已具有在途限速。验收必须同时记录这些工作及共享盘指标。

## 验证与交付

- 确定性测试：未知/陈旧/计数回退，压力与恢复迟滞，真实 DB 的硬压力来源和 gate 互斥，密度增加百倍时双范围收缩，完整大块保留成本，失败与重复外层完成。
- 事件日志测试：历史截止不能绕过、同步状态切换、后置失败退避、历史与 sidecar 计数不混用。
- 合并测试：高压缩率逻辑大输入、记录密度、超预算单叶、连续范围与溢出、每叶最多一次 busy 重写、独立准入/截止/优先机会、保留完整损坏/取消/发布校验。
- 固定合成输入比较整次合并和短合并的单轮与总工作；所有范围最终覆盖一致。此实验用于粒度和写放大验证，不标记为 20M 主网 A/B。
- 本地相关包、race 和全仓验证后提交 GitHub。服务器 pull 确定提交，独立原生 CGO/Sapling 测试与构建后切换 release，沿现有数据库恢复；保留原全局维护锁、Nile 停止状态和独立磁盘保护。
- 每个 PID 单独采样：导入/冷化/裁剪前沿、积压、各阶段耗时和预算、CPU/RSS、进程 IO 与整盘队列/延迟、freezer 工作与容量；复验原固定历史账户。低于 20M 的线上结果只作部署与当前负荷验收，不能承诺后期容量、追赶速度或同步无退步。
