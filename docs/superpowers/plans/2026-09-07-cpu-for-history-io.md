# 用富余 CPU 减少历史存储 I/O

用户确认同步时 CPU 核心远比磁盘 I/O 富余。本轮沿用完整历史、固定磁盘、MySQL 不迁移和不启动生产 gtron 的约束，在本地继续实现与验证。

目标从单次压缩 CPU 用时改为：每个有效历史版本的物理读写量、端到端冷化墙钟时间、前台关键路径延迟和内存峰值。额外 CPU 时间不等于同等墙钟退让；也不能把一个串行阶段慢简单归因于“CPU 不够”。

1. V3 单文件改为有界并行压缩、按原顺序提交，保持相同格式与字节确定性。CPU worker 不直接写文件或发布进度；锚点与引用仍按顺序落盘。限制任务数及在途 raw+encoded 预留字节，错误/取消必须 join 全部任务。
2. 对大连续输入并行计算 Gear 候选边界，再顺序应用原 min/max 规则。利用 64 次左移后旧状态完全消失的性质，使结果与原逐字节 Splitter 相同；小输入继续原路径，候选过密时有界回退。用不同分片、初始 pending、低熵和故障输入验证完全一致。
3. 热 block pack 复用大输入并行切块，以减少压缩进入前台提交路径的墙钟延迟。重新按减少 WAL/SST 的实际字节及可用 I/O 比较默认选择，而非只因增加 CPU 就关闭。保持同包引用、旧解码界限和收益门。
4. 用现有窗口约束比较不同 zstd 档位对账户/存储的空间收益；只有真实更小且解码/内存合格的方案才接入。不能把 zstd 数字级别误当作本实现中不同算法档位。
5. 建立明确标注的共享 I/O 模型，输入是真实 factory 输出与 CPU/墙钟测量，区分共同源读取、最终输出、spool 和参数化 LSM 放大。模型不是生产磁盘实测，不用简单文件压缩倍数冒充同步加速倍数。

验证：串行/并行字节完全一致，所有历史查询与回滚、损坏/取消/Reset、并发与内存上限；对比 1/2/4/8 workers；关键路径 race 和全仓测试；不部署或操作生产数据库。
