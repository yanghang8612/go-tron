# 冷化压力恢复与准备流水线后续优化

用户授权继续优化、测试、提交并部署。沿用现有主网数据库和全部历史查询；本轮不改数据格式、段大小、共识或外部 API。

## 依据

上一版 `849a336b` 的完整十分钟窗口中，状态净追赶 8,078 块；正文与交易索引各推进 65,536 块，索引债务持平。索引两次因完成时健康复查失败，等待至本批开始后五分钟。正文完成约 74.5 秒的整段，期间状态发布的可见点约 90 秒不变。

新一次 30.11 秒 CPU profile 共计 202.54 CPU 秒（约 6.73 核），捕获正文冷化：V2 frame 编码累计 49.56 CPU 秒，记录准备 34.09 CPU 秒，其中外置日志紧凑转换 17.83 CPU 秒。后者属于准备成本，不能重复相加；该短样本不代表整个同步过程平均 CPU 占用。

## 实施

1. 将索引实际整批工作恢复时刻与软压力探针时刻分开。软压力采用有界复查，两个独立、新鲜且有间隔的健康观测后恢复；不重复计算缓存样本。未知和硬压力保守，实际错误截止独立且不可被健康观测清除。保持 8,192 块叶、发布后删除、共享 gate 和日志节流。导出准入/完成原因以及绝对等待时刻，解决旧 healthy 和 recovery gauge 易被误读的问题。
2. 回执紧凑转换和外置日志检查复用同一批 wire 交易哈希，并复用已解码的紧凑 TransactionRet。保留 direct 入口原有完整验证；不混用 typed 交易哈希与 wire 哈希。先做现有 wire strip，再解析其实际结果，保留异常回退、未知/重复字段、创世空行、普通空行、无日志和负收益外置行为。
3. 正文准备改为单 producer 串行读源、固定数量 CPU worker、顺序消费的有界流水线，使读源与转换重叠。限制在途行数和输入容量，超大行独占；训练字典先于异步读源启动，每表 writer 在任何返回路径都先 Close/join，再进行验证或下一表。磁盘读源不增加并发，压缩、验证、fsync、manifest 和热删除边界保持原样。

暂不缩小 65,536 块段：小段会增加字典、文件和恢复间隔频率；已有崩溃恢复还依赖已发布的精确 Count，不能只换默认值或在持有 freezer 锁时临时释放共享 gate。

## 验证与交付

针对压力恢复、真实小批取消/失败、重复样本、并发 release、流水线排序/源互斥/借用缓冲/超大记录/取消/join、异常 protobuf 逐字节及错误行为做回归与 race。含 protobuf map 的成功外置结果按有效 envelope 和解码语义比较，避免把已有非确定性 marshal 顺序当差异。

同输入基准分别测回执去重与准备流水线，重测试完成后串行计时；验证输出和空间，不把组件结果称为全节点倍数。服务器原生测试/构建通过后按已授权流程部署，复验历史查询与连续完整窗口，记录索引债务、状态净追赶、正文完成和 CPU/共享盘压力。20M 以上表现与固定盘最终容量仍须真实数据验证。
