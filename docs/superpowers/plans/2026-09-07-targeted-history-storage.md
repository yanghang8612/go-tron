# 账户、委托历史和冷化积压的生产路径优化

依据 `../specs/2026-09-07-fresh-history-format.md` 与主网只读业务样本；本轮只在本地实现、测试，不启动服务器 gtron。

本轮先交付可独立验证的物理表示及调度改动。持久 journal 绕过 LSM、跨区块热 blob 引用和委托关系物理分页仍不实施：它们需要额外的原子提交、回滚与回收协议。

1. 账户 V5 envelope：默认 KV root 和零/重复 code hash 使用可逆短表示，保留内层完整账户 core、非默认值、地址和未知字段；生产写入、所有读取与代码引用扫描共同验证。
2. 冷历史压缩容器 V3：内容定义切块（8–128 KiB），有限字典中完整相同的块复用物理锚页。保持逻辑 V6 record 和索引 offset 不变，禁止多跳引用。页表分块校验与稀疏目录控制打开和随机读成本。复用候选必须逐字节比较；随机读校验 CRC，发布沿用完整 SHA/覆盖验证。
3. 热历史可选优化范围限于一个原子 block pack 内：大值重复时复用完整块，还原原有 RLP 字节。引用不能跨数据库 value 或区块。没有多份大值的普通块仍走现有低成本路径；必须对比收益、编码时间与解码成本后决定默认行为。
4. 基础冷历史发布后，在重型合并及其他派生工作之前回收已验证覆盖的热历史。保留原来的时间范围、文件校验、重组及事件覆盖检查；重型后续工作失败不撤销已经安全完成的热删。
5. 调度补充热历史 SST 估算字节数与写入卷剩余容量。SST 估算低频缓存，不遍历所有值；估算包含旧版本，不能冒充可回收量。默认阈值按卷容量比例设置并允许显式覆盖；低于新构建准入空间时暂停新冷构建，已覆盖热删仍可执行。准入水位不等于文件写入峰值限额。
6. 压力下维持小批、完整区块、同一个重型任务门和恢复间隔；限制每轮合并数量。错误、取消、无进展不能触发无间隔重试。

验收：账户语义/字节保真；热 pack 正常/借用读取、回滚、损坏与大小上限；冷构建→索引查询→混合版本合并→重开→完整验证；早热删顺序和失败/取消测试；定向 benchmark 后运行受影响包及全仓测试。真实主网全量压缩率及在线同步吞吐只在后续受控回放测量，不能用合成 fixture 推算整库结果。
