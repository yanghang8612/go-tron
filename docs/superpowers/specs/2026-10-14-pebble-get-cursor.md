# Bounded snapshot Get cursor

Baseline: `8bf634fb15eca46804544c59a672bd3aa18dbacf`. Production capacity is
8192 MiB, independently of this interface change. No cache budget, concurrency,
GC, table format, key ordering, encoding or consensus behavior changes here.
Ordinary DB.Get, Snapshot.Get, Batch.Get and merged Iterator are unchanged.

## Scope

Pebble v1.1.5 Get already searches memtables and LSM levels lazily, stopping
once MVCC resolution finds the answer. Each lookup constructs and closes SST
iterators, losing their current index/data block handles. The new
`Snapshot.NewGetCursor` retains at most four point/range-deletion iterator
pairs, while reusing upstream getIter and Iterator for all resolution. It does
not implement a Set-only fast path or seek every overlapping level eagerly.

The repository uses a local third_party Pebble module through go.mod replace.
Runtime source files and all platform variants in selected runtime package
directories are copied verbatim from v1.1.5, with LICENSE and upstream module
metadata. No module-cache modification, unsafe or linkname is used.
UPSTREAM_FILES.json records each original source SHA; the only new runtime file
is get_cursor.go. Upstream fixtures, tools and broad test corpus are excluded.

## Ownership and errors

A cursor is owned by one reader. Independent cursors may run concurrently. It
pins one readState and the original snapshot sequence until Close. Reads still
apply Get's memtable sequence filter: a mutable memtable may receive newer
writes after construction. Close cursors before Snapshot.Close and DB.Close; the
existing engine lifecycle lease remains in force in the go-tron wrapper.

Get returns read-only bytes borrowed until ReleaseValue, the next Get or Close;
only one value may be borrowed. The wrapper constructs the GetCursor lazily on
its first in-prefix read, so unused/out-of-prefix wrappers allocate no GetCursor
or extra readState. It consumes borrowed values synchronously and defers
ReleaseValue through callback error and panic. Timing stops after lookup, so
existing Get wall metrics exclude callbacks. Close errors remain observable. The
wrapper recognizes absence only for exact ErrNotFound; a joined error containing
ErrNotFound and an I/O/cleanup failure must propagate and must not fill a
negative application-cache entry. ValueAndErr reports a lazy value fetch failure
explicitly; the reference result is Snapshot.Get plus its required closer, whose
final error must also be checked.

Each lookup borrows the upstream getIterAllocPool allocation. Iterator.Close
clears and returns it; the cursor must never inspect that allocation afterwards,
including keyBuf/get/Iterator fields, because another reader may immediately
reuse it. Only the cursor's active/pointer fields are cleared afterwards. The
newIters method value is bound once at cursor creation, not once per key.

An operation error triggers complete table cleanup in that operation. The error
supplied by upstream Iterator.Close and subsequent retained-table cleanup errors
are joined so errors.Is can observe distinct surfaced failures. Upstream
Iterator and individual table-close first-error precedence is preserved: for
example a Merger.Finish error can hide a secondary error from its value closer,
while that closer is still called exactly once. This API does not claim to
recover errors suppressed inside upstream cleanup. Subsequent Get calls on that
poisoned cursor report the operation error. ReleaseValue with no active value is
nil; Close reports only fresh cleanup errors, never an error already delivered
by Get/ReleaseValue. This is essential: a speculative prefetch failure may be
ignored and retried by an independent foreground cursor, and must not reappear
as session.Close/whole-fold failure. Actual final table or merge-value close
failures surfaced by upstream must still be reported; with no primary error a
value-closer failure is observable. Every cleanup attempts all resources even
after an earlier failure.

## Bounded SST retention

The private tableNewIters adapter accepts only the default options generated by
Get; incompatible bounds/filters/stats use uncached upstream construction.
Matching requires the same immutable FileMetadata and level. An entry visited by
a Get stays leased through that entire lookup and value consumption, even when
getIter logically closes its point/range iterator. getIter can retain a range
tombstone Span after logical Close. A leased entry cannot be evicted or returned
again; if all four entries are leased, additional tables follow the original
uncached ownership path. Thus long merge chains and many L0 sublevels do not
grow a table cache according to historical SST count.

Logical Close returns iterator.Error without physically closing retained
iterators. Absolute SeekPrefixGE/keyspan.Get positions them again next time.
Actual eviction/final cleanup closes point and range iterators exactly once. The
filteredIter.MaybeFilteredKeys extension is preserved. Each slot also owns its
one-element filter backing: upstream levelIter.filtersBuf is temporary, and
retained SST obsolete-point filterers must not borrow that mutable buffer.

Four entries bound retained iterator/reader handles, not bytes. Large data/index
blocks, range-deletion blocks, value-block buffers and read handles vary by SST.
Pinned readState also delays physical obsolete-file/memtable reclamation for the
short fold session. This is additional memory to measure, not a reservation
inside the configured Pebble block-cache budget, and not an RSS guarantee.
Existing 32 GiB cgroup protection remains unchanged.

## Measurements and validation

Cursor-local counters record table requests, successful newIters constructions,
reuse, uncached fallback, eviction and maximum retained entries. Only cursor
Close publishes them to process metrics. Table construction counts are not
physical file opens or device IO. Existing Get/calls/nanos counters keep their
meaning; new counters have no synthetic historical baseline.

Root-module tests compare against Snapshot.Get with full closer handling and
cover mutable memtables, late cursors on old snapshots, flush/compaction,
empty/long/0xff keys, custom Split, multi-table merge and deletion/tombstone
cases, different key orders and concurrent cursors. Real wrapper/blockbuffer
sessions test speculative I/O failure followed by independent foreground retry
and successful Close. Nested-module tests cover leased-slot fallback, distinct
read/close errors, poisoned reads and exactly-once value closer ownership. The
nested module requires its own explicit test/race command; root go test ./...
does not discover its tests.

BenchmarkGetCursorLifecycle compares Snapshot.Get and GetCursor in the same
fork, with identical input/cache budgets, including creation/read/release/Close
for 0/1/4/16/256-key sessions. It reports real VFS ReadAt and table reuse. Full
8-block commitment fold/publication/flush/read traces compare isolated baseline
and candidate roots, durable reads, allocations and elapsed pipeline time. That
synthetic fixture configures64 partitions but activates only one; raw helper
gains cannot establish node throughput. Native validation and stable online
sampling are separate evidence, and existing cache/memory warmup effects must
not be attributed to the new interface.
