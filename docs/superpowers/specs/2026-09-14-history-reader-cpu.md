# 共享历史读侧的解码分配

2026-09-14。状态：实现与验证中。继续用户授权的 master 开发和 GitHub 原生部署。

上一轮 cda09766 已减少 writer 重复 SHA 和委托 membership 分配。部署后 45 秒
CPU 样本里，共享 reader 整包解码约 10.42 CPU 秒，其中 SHA 约 8.58 秒；该样本
并非同高度对照，不能直接预测本轮同步收益。固定输入 oracle 与原生基准决定是否发布。

## 最小修改

共享 pack 已预检完整引用表和总输出大小。将 Snappy 片段直接解码到 pack 自有、
尚未公开的输出区间，减少每个压缩片段的临时大分配和后续复制；raw 片段仍只复制一次。
保持普通 nil-destination chunk decoder 和 writer 的字节所有权、错误及认证语义。

每个引用继续执行原来的 Get/Has 及 envelope、decoded length、Snappy、chunk SHA
检查；最终验证完整 pack SHA，失败仍返回 nil。原数据表示、引用顺序、错误优先级、
预检 I/O 上界、调用者快照和回收守卫均保持。不得以缓存命中跳过数据库读取。

先不叠加同包重复引用认证复用。若直接解码收益有限，需独立证明后一方案的唯一
引用开销和有界索引内存，再决定是否纳入，不能由热点份额推断安全可省的校验。

## 验证与发布

逐字冻结 cda09766 的 reader 为独立 oracle，对照所有输出、错误、读取顺序、
故障前缀和输入/输出所有权。覆盖 raw/Snappy、唯一/重复引用、混合、小包、大包、
损坏/缺失、边界长度和公共 history/as-of/冷构建调用路径。固定输入同时报告完整
方法耗时、分配次数、分配字节及噪声范围，不将 B/op 等同于 RSS。

Go 1.25.5 本地回归/race 与原生 Sapling 验收通过后才激活。延续 cda09766 及所有
祖先兼容 reader 的永久标记和回滚路径。线上使用新旧进程各自完整窗口，记录
冷迁移/裁剪/body/index 实际水位、eligible lag、历史 canary、GC、shadow 错误和独立 du。
不以低样本启动时段覆盖主窗口，也不把存储字节等价的 CPU 改动当作磁盘格式优化。

同时只读定位 body/index 分段发布条件和影子合约返回状态不匹配；诊断结论与本轮
reader 修改分开验证，未定位根因时不修改覆盖门槛或共识规则。
