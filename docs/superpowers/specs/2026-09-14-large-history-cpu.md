# 大旧值的重复哈希与委托索引分配

2026-09-14。状态：已实现并部署 cda09766，完成原生验收与部署后采样。
用户授权继续优化、直接 master 开发及 GitHub 原生部署，沿用共享热历史的
兼容 reader、回滚保护和现有资源预算。

## 依据与范围

上一轮不同高度的 6 分钟窗口中，每笔交易的历史 RLP 输入约增加 7.17 倍，
45 秒 CPU 样本的 SHA256 占比约 24%，委托名单 membership 构建约占 8.28 CPU 秒。
这些是特定负载下的热点，不是同高度版本回归证明。此次新采样仍使用线上
`64ed654f` 作为基线，固定输入旧实现 oracle 用于判断修改本身的收益。

仅处理两项机械重复工作：

1. 委托名单 membership 保留 `map[string]struct{}` 与原匹配规则，将初始 key
   字节批量复制到私有不可变字符串，避免逐地址小分配。任意长度、空值、重复项、
   顺序、protobuf 内容、缓存所有权与失效规则不变。原保守 charge、32 MiB、1024 行
   和 16 项阈值不变；删除后不减少历史分配 charge，覆盖 arena 的保留。
2. 共享历史 writer 已持有本次候选 chunk 的 SHA256 证明。已有存储片段仍须每次
   Get、完整解码并逐字节比较；相等时可由相等性继承本次候选证明，省去第二次 SHA。
   不相等时保留旧 SHA 检查及 hash mismatch / digest collision 错误顺序。
   普通 reader 的逐片段与整包 SHA、预算与引用表预检保持严格校验。

不建立跨操作的已验证 chunk 缓存，不改变持久化格式、CDC 边界、种子开销上限、
分桶、原子发布顺序、snapshot 视图或 GC 门槛，也不调整任何并发与内存预算。

## 验证与发布

冻结旧函数作为 oracle，比较输入接受范围、输出字节、错误、写入及故障副作用。
委托路径需覆盖输入所有权、预算边界、generic mutation 失效、回滚、历史和 root；
共享路径需覆盖 raw/Snappy、损坏/缺失、同 bucket 重复、种子和回退。
固定输入同时测量完整方法及窄热点，记录分配和耗时，避免只展示局部上限。

本地及服务器使用 Go 1.25.5；原生构建保留 Sapling。部署保护指定 `64ed654f`
为即时兼容回滚版本，继续保护所有祖先 v3 reader 标记。准备和测试通过后才切换。
部署前后分别在同一进程内取样，不跨重启相减累计计数；同时记录历史 canary、
状态/区块/index 积压、共享 GC、错误、磁盘各目录。不同高度的吞吐变化只作观测，
不能直接归因于本次优化。

实际基准、core 既有失败限制、部署凭据和线上观测见
[完整记录](../../dev/large-history-optimization-20260914.md)。固定输入局部收益成立；
不同高度线上全窗口尚未证明整体提速，冷迁移积压仍缓慢增长。
